## 发现的问题 / 风险

### 问题 1：登录后刷新回到 login 页面
- **根因**：`/me` 端点依赖 `get_current_principal`，当 API Key 鉴权启用时，缺少 `X-API-Key` 就直接返回 403，导致 `X-Auth-Token` session token 验证代码被跳过。
- **修复**：`/me` 去掉 `get_current_principal` 硬依赖，改为自行处理 API Key 回退（先 session → 再 API Key → 最后 anonymous）；session token 增加 15 分钟滑动过期；前端 `getAuthToken` 增加客户端过期检查。

### 问题 2：`GET /api/ui/v1/auth/users` 返回 401 Unauthorized
- **根因**：与问题 1 相同，session auth 链路被 API Key 鉴权阻断，`require_admin` / `get_current_user_with_session` 无法通过 session token 验证。
- **修复**：问题 1 的修复同时解决了此问题。`/users` 端点通过 `X-Auth-Token` 头传入 session token，由 `get_current_user_with_session` 独立校验，不再受 `get_current_principal` 影响。

- 当前 sandbox 仍无法稳定启动真实浏览器引擎，因此 `WEB-S8-006` 的真实浏览器 E2E 回补仍需要外部可运行环境。
- 项目级恢复与配置级恢复必须继续分层，避免后续文档和实现再次混淆职责。
