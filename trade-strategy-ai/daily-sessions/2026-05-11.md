## 发现的问题 / 风险

### 问题 1：登录后刷新回到 login 页面
- **根因**：`/me` 端点依赖 `get_current_principal`，当 API Key 鉴权启用时没有 `X-API-Key` 就直接返回 403，session token 验证代码（`X-Auth-Token` 头）被跳过。
- **修复**：`/me` 去掉 `get_current_principal` 硬依赖，改为自行处理 API Key 回退；增加 15 分钟滑动过期；前端 token 存储加入过期检查。

### 问题 2：`GET /api/ui/v1/auth/users` 返回 401 Unauthorized
- **根因**：同上，session auth 链路在整个 `/me` 端点被 API Key 鉴权阻断，导致用户管理接口（依赖 `get_current_user_with_session` → `require_admin`）也无法通过 session token 验证。
- **修复**：问题 1 的修复同时解决了此问题。`/users` 端点通过 `X-Auth-Token` 头传入 session token，由 `get_current_user_with_session` 独立校验，不再受 `get_current_principal` 影响。

- 当前环境无法稳定启动真实浏览器引擎，因此 `WEB-S8-006` 对应的真实浏览器回补仍需要放到可运行 Chromium / Firefox 的环境中处理。
- 项目级恢复和配置级恢复的边界已经明确，后续新增恢复能力时要继续保持这个分层。
