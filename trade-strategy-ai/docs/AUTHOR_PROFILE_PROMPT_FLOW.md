# 作者画像 Prompt 使用流程

## 1. 初始处理 100+ 篇文章

```text
每篇普通文章
→ article_analysis_v1（通常一次主调用）
→ Schema 校验
→ 必要时 article_analysis_repair_v1（最多一次）
```

保存结构化结果后：

```text
去重和聚类
→ 每 10～20 篇运行 author_method_profile_batch_v1
```

程序同时生成规则统计：

```text
规则指纹
→ 规则族
→ 规则类型和数据依赖统计
→ author_rule_profile_summary_v1
```

## 1.1 规则审核流程

单篇规则提取后：

```text
rule_extraction_v1
→ Schema 校验
→ 自动审核和风险分级
→ 低风险规则进入待回测
→ 歧义和高风险规则进入人工审核 UI
```

人工审核后的规则才可以形成正式 RuleVersion。

即使自动审核通过，规则准备加入正式策略时仍需人工确认其回测结果和正式适用性。

## 2. 回测完成后

程序产生：

- 回测指标
- 分市场状态指标
- 样本量
- OHLCV/Kaipan 数据覆盖
- 规则适用性结果

然后运行：

```text
author_validated_profile_v1
```

## 3. 合并作者画像

输入：

- 批次方法画像
- 规则画像
- 验证画像
- 上一版本画像

运行：

```text
author_profile_merge_v1
```

输出只能是 `draft`，人工审核后由应用服务发布。

## 4. 增量更新

新文章：

```text
只处理新文章
→ 更新所在聚类
→ 必要时更新批次画像
```

新回测或累计盘后证据：

```text
author_profile_revision_v1
```

只有决策为 `create_draft` 时才进入画像合并流程。

## 5. 与盘前预测关系

作者画像是辅助信息，不是最终决策源。

```text
规则适用性
> 当前市场状态
> 正式策略
> 数据质量
> 作者验证画像
> 作者方法画像
```

## 6. 建议批次大小

- 每批 10～20 篇结构化文章。
- 同一批优先保持同一时间段或主题。
- 不要直接输入全文。
- 每批附带文章 ID、发布时间和证据引用。


## 7. 初始回归样本

无需用户预先准备黄金样本。

系统从现有文章中自动抽取候选样本，AI 完成分类，用户确认后固定。固定样本通过后，再处理全部文章。

回归样本用于比较：

- 文章结构化质量
- 规则提取质量
- 市场状态未声明处理
- 自动审核结果
- 重复和冲突识别
- 作者画像批次汇总稳定性


详细调用编排见 `trade-strategy-ai/docs/LLM-Prompt-Orchestration.md`。
