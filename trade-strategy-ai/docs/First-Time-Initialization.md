# 首次初始化指南

本文档面向管理员。普通业务用户不需要按本指南操作。

## 初始化目标

首次初始化要完成：

- 准备运行环境和数据库。
- 配置访问权限和密钥来源。
- 执行数据库迁移。
- 检查系统健康。
- 准备基础数据。
- 确认正式产品路径可用。

不要把大范围历史回灌、实时外部拉取或批量 AI 处理作为默认初始化步骤。初始化只做最小可验证准备；后续数据补齐应通过系统管理中的明确维护动作执行。

## 1. 准备配置

管理员要做什么：

- 从模板配置创建当前环境配置。
- 通过部署环境注入数据库连接、访问密钥和外部服务凭据。
- 确认真实凭据不会写入仓库。

系统会做什么：

- 读取当前环境配置和运行时变量。
- 对敏感值只显示是否已设置，不显示明文。

输出结果：

- 可启动的运行配置。
- 脱敏的配置检查结果。

下一步：

- 执行环境检查。

## 2. 执行环境检查

建议命令：

```bash
python -m scripts.web_local env-check
```

预期结果：

- 显示关键配置是否已设置。
- 敏感值脱敏。
- 不输出真实密钥。

如果结果不可用：

- 补齐运行时变量。
- 检查配置文件来源。
- 不要把真实凭据提交到仓库。

## 3. 初始化数据库

管理员要做什么：

- 确认数据库服务可访问。
- 执行迁移。
- 检查迁移版本。

建议命令：

```bash
python -m cli.main db-check --config config/app.template.yaml
python -m alembic -c src/db/migrations/alembic.ini current
python -m cli.main db-migrate --config config/app.template.yaml
```

系统会做什么：

- 检查数据库连接。
- 应用未执行的迁移。
- 保留迁移历史。

输出结果：

- 数据库可访问。
- 当前迁移版本与仓库迁移链一致。

如果失败：

- 先备份现有数据库。
- 查看迁移错误。
- 不要手工删除历史数据来绕过失败。

## 4. 启动服务并检查健康

管理员要做什么：

- 启动后端服务。
- 构建并启动前端。
- 打开 `系统管理` → `系统状态` 和 `系统管理` → `系统健康`。

系统会做什么：

- 检查后端、数据库、前端静态资源和关键依赖。

输出结果：

- 健康、降级或不可用状态。
- 影响范围和修复建议。

下一步：

- 状态正常后，准备基础数据。

## 5. 准备基础数据

管理员要做什么：

- 确认历史行情数据版本。
- 确认盘前和盘后数据来源可用。
- 确认市场状态模型版本可用。

系统会做什么：

- 在系统管理中展示数据范围、覆盖率和可用时间。

输出结果：

- 可用于回测的固定数据版本。
- 可用于每日盘前盘后的市场快照。

如果数据不足：

- 在 `系统管理` → `数据与调度` 中执行明确的补齐动作。
- 不要把实时拉取或大范围补数据作为部署成功标准。

## 6. 建立第一条正式业务链路

管理员或授权用户要做什么：

- 按 [快速开始](Quick-Start.md) 导入文章、审核规则、回测、发布策略。
- 再生成盘前计划和盘后复盘。

系统会做什么：

- 生成可追溯的文章版本、规则版本、数据版本、回测结果、规则适用性、作者画像、策略版本、每日计划和优化建议。

输出结果：

- 第一条可验证的正式链路。

下一步：

- 普通用户改用 [完整使用手册](User-Manual.md) 日常操作。
- 管理员按 [管理员运维指南](Admin-Operations-Guide.md) 维护系统。
