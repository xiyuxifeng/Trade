# New-Web-Migration-Matrix

> 对应任务：`NW-V1-S0-002 P0 建立迁移矩阵`
>
> 目标：建立旧 CLI、现有 UI Job、现有 Workflow 到新 Web/API/Worker 架构的完整映射。

## 说明

- `当前 Service` 记录当前已经存在的服务模块或运行时入口。
- `当前 API` 记录当前已经存在的 Web/API 入口。
- `新 Application Service` 记录迁移后应收敛的应用服务边界。
- `新 Step` 记录未来 Step Registry / Workflow Runner 中对应的执行动作。
- `新 Workflow` 记录未来 Web 入口中的编排壳或业务工作台。
- `新 Job Type` 记录迁移后应保持唯一的 Job 白名单标识。
- `迁移状态` 使用以下值：
  - `web-workflow`
  - `web-job`
  - `web-query`
  - `dev-only`
  - `deprecated`
  - `remove-later`

## 4. 迁移规则

1. `web-workflow` 表示该能力最终应通过 Web 工作流入口触发，并由 Job Center 追踪。
2. `web-job` 表示该能力在 Web 中应保留 Job 级入口，但仍可能通过 Workflow 聚合。
3. `web-query` 表示该能力以查询/浏览为主，后续以 Web 查询入口为准。
4. `dev-only` 表示该命令只保留给开发调试或运行守护，不作为产品入口。
5. `deprecated` / `remove-later` 表示不进入第一版产品入口，但必须在后续任务中明确处理退出条件。

## 5. 当前覆盖结论

- 现有 JobDefinition 已全部纳入迁移视图。
- 现有 WorkflowDefinition 已全部纳入迁移视图。
- 现有 CLI 命令已按能力家族纳入迁移视图。
- 不进入 Web 产品入口的命令已明确标记为 `dev-only` 或 `remove-later`。
