# New-Web V1 User Manual

> 面向真实用户的 V1 Web 操作手册。
> 本文只覆盖当前已经验收的 V1 主链路，不把 V2/V3 能力写成前置条件。

## 1. 你可以用 Web 完成什么

V1 的目标是让你通过 Web 完成 `article_pipeline` 的提交、查看和回溯，而不是手工串 CLI。

你可以在 Web 中完成这些事情：

- 进入 `article_pipeline` 页面并提交运行。
- 在 `任务` 页面查看任务列表。
- 在 `任务详情` 页面查看步骤时间线、日志、产物和配置快照。
- 在 `产物` 页面查看和下载产物。
- 在 `报告` 页面查看盘前日报和盘后考核结果。
- 在 `设置` 页面查看和保存配置。

## 2. 推荐操作路径

### 2.1 运行 `article_pipeline`

1. 打开 `/articles`。
2. 在 `article_pipeline` 页面检查参数。
3. 如果页面提示参数不完整，先补齐必填项。
4. 点击 `运行 article_pipeline`。
5. 如果需要确认，按页面提示完成二次确认。
6. 提交后，页面会跳转到新建的 `任务详情`。

### 2.2 查看运行结果

在 `任务详情` 页面，你应当按这个顺序查看：

1. 任务状态。
2. 步骤时间线。
3. 日志。
4. 产物。
5. 配置快照。

如果任务成功，你可以直接从该页打开产物或进入 `产物` 页面下载。

如果任务失败，你应优先查看：

- 失败原因。
- 最近日志。
- 步骤时间线中最后一个失败步骤。
- 配置快照是否和你预期一致。
- 产物区是否存在缺失或未生成的结果。

### 2.3 取消或重跑任务

在 `任务详情` 页面：

- `取消任务` 用于停止仍在运行的任务。
- `重新运行任务` 用于按当前任务参数重新发起一次执行。

如果任务已经完成，`重新运行任务` 会创建新的任务记录，不会覆盖旧任务。

## 3. 关键页面说明

### 3.1 `article_pipeline`

路径：`/articles`

这是 `article_pipeline` 的唯一对外入口。

你会看到：

- 当前流程说明。
- 运行参数。
- 最近运行记录。

### 3.2 `任务`

路径：`/jobs`

这里展示最近任务记录。

你可以：

- 按状态筛选。
- 按任务类型筛选。
- 按创建者筛选。
- 打开某条任务详情。

### 3.3 `任务详情`

路径：`/jobs/:jobId`

这里是最重要的解释页。

你可以看到：

- 任务基本信息。
- 步骤时间线。
- 日志。
- 产物面板。
- 配置快照面板。

### 3.4 `产物`

路径：`/artifacts`

这里展示产物中心。

你可以：

- 查看产物摘要。
- 打开产物详情。
- 下载产物。

### 3.5 `报告`

路径：`/reports`

这里展示：

- 盘前日报。
- 盘后考核结果。

### 3.6 `设置`

路径：`/settings`

这里展示当前配置和配置保存能力。

你可以：

- 查看配置摘要。
- 预览配置差异。
- 保存配置。
- 查看备份和恢复记录。

## 4. 失败后怎么看问题

如果 `article_pipeline` 运行失败，请按下面顺序排查：

1. 打开 `任务详情`。
2. 查看失败步骤和错误消息。
3. 打开日志区，确认最后一次运行输出。
4. 检查配置快照，看当前运行实际使用的配置。
5. 检查产物区，确认是否有部分中间结果已经生成。
6. 如果问题和权限有关，确认你当前身份是否为 `operator`。

## 5. 权限说明

V1 里常见的两个权限角色是：

- `viewer`：只能看结果，不能提交运行。
- `operator`：可以提交运行、取消任务、重跑任务和保存配置。

如果你看到“当前身份仅可查看参数”之类提示，说明当前账号没有提交权限。

## 6. V1 范围内和 V1 之外的能力

### 6.1 V1 已交付

- `article_pipeline` 提交与回溯。
- Job 列表、详情和步骤时间线。
- 产物查看与下载。
- 配置快照脱敏展示。
- 报告查看。
- 基础权限控制和错误提示。

### 6.2 明确留给后续版本

- 独立 Artifact Center。
- 正式 Profile 工作台。
- 更复杂的 workflow 管理。
- 跨 Job 搜索与聚合分析。

这些能力不是 V1 使用 Web 的前置条件。

## 7. 常见问题

### 7.1 为什么我提交后会跳到任务详情？

因为 V1 的设计目标是让你先看到运行结果，再继续查看日志、产物和配置快照。

### 7.2 为什么有些页面看起来像“工作台”，但又不是完整产品？

因为 V1 是可交付收口版本，页面已经规范化，但还没有进入 V2 的正式信息架构重构。

### 7.3 为什么文档里还会提到 CLI？

CLI 只保留给内部回归和 smoke gate，不是你完成 V1 的正式路径。
