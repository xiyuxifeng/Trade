# 最终回测与优化所需的基础数据

为了进行最终的回测（Backtesting）和优化（Optimization），需要按顺序抓取、生成和处理一系列基础数据。本文档旨在说明所需数据的类型、生成流程以及对应的CLI命令，确保整个链路的数据完整性和可追溯性。

## 数据准备流程

整个数据准备和分析流程遵循以下顺序，后续步骤依赖于前序步骤的产出。这是一个从原始信息到策略评估的完整数据链路：

1.  **抓取文章数据**: 从数据源（如淘股吧）抓取交易员的文章，这是策略思想和规则的原始来源。
2.  **提取规则与策略**: 对抓取的文章进行分析，提取结构化的交易规则，并将其存入规则池。
3.  **抓取OHLCV数据**: 获取所有标的（股票、指数等）的历史日线行情数据，这是所有量化分析的基础。
4.  **构建市场快照**: 基于每日的盘后原始数据，生成结构化的市场快照，包括热点题材、题材成分股、强势股等。这些快照是策略在特定日期进行决策的市场环境依据。
5.  **构建策略版本**: 为指定交易员在特定日期创建一个固化的策略版本，该版本包含了其交易逻辑和所依赖的规则。
6.  **运行回测**: 使用历史OHLCV数据、市场快照和固化的策略版本，对特定交易员的策略进行模拟交易，生成详细的回测结果。
7.  **执行优化**: 基于回测结果，筛选表现优异的交易员，并为他们的策略提供优化建议或生成候选策略版本。

## 基础数据与CLI命令详解

### 1. 文章数据

-   **目标**: 抓取并存储交易员的文章原文，作为策略规则提取的输入。
-   **CLI命令**: `crawl`
-   **说明**: 此命令根据 `config/app.yaml` 中的配置，从指定源抓取文章。
-   **常用示例**:
    -   抓取少量文章进行测试：
        ```bash
        python -m cli.main crawl --max-articles 10
        ```

### 2. 规则与策略提取

-   **目标**: 从文章中提取交易规则，并存入规则池（Rule Pool）进行管理。
-   **CLI命令**: `extract-articles`
-   **说明**: 此命令利用LLM或启发式方法分析文章，识别并抽取出结构化的交易规则。
-   **常用示例**:
    -   从数据库中抽取最新的文章：
        ```bash
        python -m cli.main extract-articles --limit 50
        ```

### 3. OHLCV 行情数据

-   **目标**: 抓取并存储所有相关标的（股票、指数等）的历史日线价格（开、高、低、收）和成交量数据。
-   **CLI命令**: `ohlcv crawl`
-   **说明**: 此命令用于从配置的数据源（如AKShare）获取数据并存入项目数据库。它是所有后续分析的数据基石。
-   **常用示例**:
    -   **增量更新**：获取自上次更新以来的最新交易日数据。这是日常维护的常用命令。
        ```bash
        python -m cli.main ohlcv crawl --mode incremental
        ```
    -   **全量抓取**：获取指定时间段内的所有历史数据。适用于项目初始化或数据修复。
        ```bash
        python -m cli.main ohlcv crawl --mode full --from 2023-01-01 --to 2024-05-08
        ```

### 4. 市场快照数据 (Market Snapshot)

-   **目标**: 将每日的原始市场数据（例如，来自“开盘啦”等第三方服务的热点、题材、强势股列表）处理成标准格式的快照文件，供回测引擎在模拟环境中加载。
-   **CLI命令**: `snapshot build`
-   **说明**: 此命令处理 `data/kaipan/raw/` 目录下的原始数据，生成快照并默认保存到 `data/market_universe/snapshots/` 目录。快照是策略回溯历史情境的关键。
-   **常用示例**:
    -   **在线处理指定日期**：获取指定日期的在线数据并构建快照。
        ```bash
        python -m cli.main snapshot build --date 2024-05-07
        ```
    -   **在线批量处理日期区间**：按起止日期批量构建快照，包含首尾日期。
        ```bash
        python -m cli.main snapshot build --start-date 2024-05-07 --end-date 2024-05-09
        ```
    -   **离线处理所有**：扫描 `raw` 目录中所有已缓存的日期数据，并批量构建快照。
        ```bash
        python -m cli.main snapshot build --offline
        ```

### 5. 策略版本 (Strategy Version)

-   **目标**: 为一个交易员在特定日期创建一个不可变的策略版本，用于回测和复现。
-   **CLI命令**: `strategy build`
-   **说明**: 该命令会打包特定交易员在该日期的所有相关规则和配置，形成一个独立的策略版本。
-   **常用示例**:
    -   为 `trader_001` 在 `2024-05-07` 创建一个策略版本：
        ```bash
        python -m cli.main strategy build --trader trader_001 --date 2024-05-07
        ```

### 6. 回测结果 (Backtest Result)

-   **目标**: 针对特定交易员的策略版本，在指定的历史时间段内运行模拟交易，以评估其历史表现。
-   **CLI命令**: `backtest run`
-   **说明**: 回测引擎会加载已准备好的OHLCV、市场快照和策略版本数据，模拟策略的每日决策过程，并输出包含每一笔模拟交易的详细记录和整体绩效摘要的报告。
-   **常用示例**:
    -   对名为 `trader_001` 的交易员在指定时间段内进行回测，并指定策略版本，将结果保存为Markdown文件：
        ```bash
        python -m cli.main backtest run --trader trader_001 --strategy-version <VERSION_ID> --from 2024-01-01 --to 2024-05-08 --output results/trader_001_backtest.md --format markdown
        ```

### 7. 优化分析数据 (Optimization Analysis Data)

-   **目标**: 基于一系列回测结果，通过算法筛选出符合特定标准（如胜率、交易次数、夏普比率等）的“活跃交易员”，为后续的策略优化和迭代提供输入。
-   **CLI命令**: `optimize filter`
-   **说明**: 此命令读取一个或多个回测生成的JSON结果文件，根据用户设定的阈值进行筛选，并输出筛选后的交易员列表。
-   **常用示例**:
    -   从 `data/backtest/` 目录下的所有回测结果中，筛选出最低胜率达到55%且交易次数不少于20次的活跃交易员：
        ```bash
        python -m cli.main optimize filter --file "data/backtest/*.json" --min-win-rate 0.55 --min-trades 20
        ```
