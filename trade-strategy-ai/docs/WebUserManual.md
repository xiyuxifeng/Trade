# Web 用户手册

> 适用范围：`trade-strategy-ai` 的 Web 管理后台。
>
> 目标：让普通用户、`admin`、`operator` 和 `viewer` 按本文即可完成登录、浏览、查询、提交任务、查看结果、修改配置和执行运维操作。
>
> 说明：本文只讲“怎么用”和“结果怎么看”，不讲实现细节。遇到高风险操作时，请先确认环境和权限，再继续。

---

## 1. 先看这几件事

### 1.1 你会用到哪些页面

- `概览`：查看系统状态、最近任务和最近产物。
- `任务`：查看任务详情、日志、产物，必要时重新运行或取消任务。
- `工作流`：按向导方式发起常用流程。
- `产物`：查看、预览和下载文件结果。
- `市场`：查询标的列表和 OHLCV K 线数据。
- `快照`：构建和查看市场快照。
- `策略实验室`：查看策略版本、候选版本和规则审核。
- `信号`：查看信号列表和上下文。
- `画像`：生成样例聚类文件。
- `市场状态`：生成市场状态快照。
- `导入`：上传交易日志、迁移 crawl 状态。
- `开盘`：执行 Kaipan 抓取、清洗和运行控制。
- `数据健康`：查看运维仪表盘和健康报告。
- `回测`：浏览回测结果、运行回测和规则验真。
- `报告`：查看盘前日报和盘后评估。
- `设置`：查看、编辑、校验、保存和恢复配置。
- `用户管理`：管理员管理用户、角色和启用状态。
- `运维`：项目级备份、恢复和回滚演练。
- `告警`：查看告警历史、确认/解决告警并发送测试告警。

### 1.2 登录和权限

- `登录`页用于用户名/密码登录。
- 登录后，顶部和侧边栏会显示当前身份。
- 常见角色有三种：
  - `viewer`：只能查看数据。
  - `operator`：可以执行大部分操作和长任务。
  - `admin`：可以修改配置、管理用户、执行备份恢复等高风险操作。

### 1.3 推荐起步顺序

如果你是第一次使用，建议按这个顺序：

1. 登录。
2. 打开 `概览`，确认系统正常。
3. 打开 `任务`，确认最近任务有结果。
4. 打开 `工作流`，从向导提交一个流程。
5. 打开 `产物` 和 `报告`，确认结果可以查看。
6. 打开 `设置`，检查配置和备份。

## 2. 常见结果怎么理解

### 2.1 任务状态

- `pending`：已创建，等待执行。
- `running`：正在执行。
- `success`：执行成功。
- `failed`：执行失败。
- `cancelled`：任务已取消。

### 2.2 配置和审核状态

- 配置分段里的 `boolean / number / json / string / null` 表示这个字段适合什么输入类型。
- 策略规则常见状态：
  - `pending`：待审核。
  - `approved`：已批准。
  - `rejected`：已拒绝。
- 策略版本常见状态：
  - `draft`：草稿。
  - `released`：已发布。
  - `archived`：已归档。
  - `candidate`：候选版本。

### 2.3 健康和风险标签

- `fresh`：数据较新。
- `stale`：数据偏旧，需要关注。
- `critical`：严重问题，需要优先处理。
- `warning`：有风险，但还不一定影响使用。
- `info`：提示信息。

### 2.4 报告字段怎么读

- `HTML`：适合直接阅读。
- `JSON`：适合核对结构化字段。
- `highlights`：核心亮点。
- `risks`：风险提示。
- `evidence` / `evidence pack`：证据引用，用于追溯。
- `ranking`：排序或评分相关特征。

## 3. 页面使用说明

## 3.1 概览

作用：
- 作为首页，集中看系统健康、最近任务和最新产物。

怎么操作：
- 登录后直接打开首页。
- 先看系统状态卡片，再看最近任务和最近产物。

怎么看结果：
- 如果系统状态正常，说明 API、数据库和关键目录大概率可用。
- 如果最近任务里有 `failed`，先点进去看原因。
- 如果最近产物为空，不一定是错误，可能只是还没有任务产出。

## 3.2 任务

作用：
- 查看所有长任务的当前状态、参数、日志、审计事件和产物。

怎么操作：
- 用上方筛选框按创建者、任务类型、状态过滤。
- 在列表里点 `详情` 查看单个任务。
- 在详情抽屉里查看参数、日志和产物。
- 如果是 `operator`，可重新运行任务；如果任务还在运行中，也可以取消任务。

怎么看结果：
- 参数区显示本次任务实际使用的参数快照。
- 日志区显示任务执行过程。
- 产物区显示这次任务生成了哪些文件。
- 审计区显示谁、在什么时间、做了什么操作。

结果含义：
- `pending`：任务还没开始。
- `running`：任务正在处理。
- `success`：这次执行结束并成功产出结果。
- `failed`：任务执行中出现错误。
- `cancelled`：任务被停止，不要把它当成正常完成。

## 3.3 工作流

作用：
- 把常用操作做成可点选的向导，适合不熟悉参数的用户。

怎么操作：
- 在左侧选择一个工作流。
- 先看 `流程总览`，确认这个流程是不是你要的。
- 再看 `步骤详情`，了解每一步需要哪些参数。
- 最后打开 `运行入口`，按表单提交。

怎么看结果：
- 工作流提交成功后，会创建一个任务，并跳转到任务中心查看。
- 如果工作流需要确认，页面会提示风险等级和确认要求。

结果含义：
- 工作流卡片上的步骤数，表示这个流程要走多少步。
- 风险标签越高，越需要先确认参数和目标。
- 参数表里的 `必填` 字段必须填，否则不能运行。

## 3.4 产物

作用：
- 集中查看所有生成文件，支持预览和下载。

怎么操作：
- 用文本、来源、任务 ID、文件类型筛选。
- 点击某个产物进入详情。
- 可预览的文件可直接在页面中查看。
- 需要离线使用时，点击下载。

怎么看结果：
- `previewable` 表示能否直接预览。
- `kind` 表示文件类型，例如 `html`、`json`、`markdown`。
- `source` 表示文件从哪个流程或模块生成。
- `job_id` 表示该文件对应的任务来源。

结果含义：
- `html`：通常是可直接阅读的报告。
- `json`：适合程序或高级用户查看结构化内容。
- `markdown` / `text`：适合快速阅读。
- `zip` / `tar.gz`：通常是打包结果，先下载再解压查看。

## 3.5 市场

作用：
- 查询标的列表，并查看某个标的的 OHLCV 历史数据和 K 线图。

怎么操作：
- 在左侧搜索标的。
- 选中一个 symbol。
- 设置开始日期和结束日期。
- 点击 `查询 OHLCV`。

怎么看结果：
- 上方摘要会显示标的总数、当前选择、数据行数、最新收盘价和价格范围。
- 中间的 K 线图用于快速判断价格走势。
- 下方表格是逐日明细，方便核对开高低收和成交量。

结果含义：
- `开盘价 / 最高价 / 最低价 / 收盘价`：每天的价格信息。
- `成交量`：当天成交数量。
- `成交额`：当天成交金额。
- 红绿颜色表示涨跌方向，收盘价高于开盘价通常为上涨。

## 3.6 快照

作用：
- 构建市场快照，作为盘前、回测和分析的输入。

怎么操作：
- 选择开始日期、结束日期和时间插槽。
- 选择快照类型：
  - `hot_topics`：热题材。
  - `topic_constituents`：题材成分股。
  - `strong_symbols`：强势标的。
  - `all`：全部类型。
- 如果需要强制重建，勾选 `Force rebuild`。
- 如果需要离线处理，勾选 `Offline mode`。
- 点击 `构建快照`。

怎么看结果：
- 页面会显示总计、热题材数量、强势标的数量等摘要。
- 构建成功后会生成一个任务，去 `任务` 页面看详细进度。
- 下方列表可查看已经生成的快照。
- 点击某个快照可查看详细内容和原始 JSON。

结果含义：
- `hot_topics`：当天热度较高的题材列表。
- `topic_constituents`：题材对应的成分股。
- `strong_symbols`：强势标的列表。
- 数量越多，不代表一定更好，主要用于判断当天市场结构。

## 3.7 策略实验室

作用：
- 统一查看策略版本、规则池、审核状态和候选版本生成入口。

怎么操作：
- 左侧先按交易员、日期、状态、类型筛选策略版本。
- 点选某个版本后，查看摘要、规则和 JSON。
- 需要新版本时，填写候选备注并点击 `生成候选版本`。
- 需要审规则时，在右侧选择规则后进行单条审核或批量审核。
- 需要建议时，选定一个版本和一条规则，点击 `运行优化建议`。

怎么看结果：
- 版本摘要会显示当前版本是否是候选、有没有规则快照、有哪些推荐建议。
- 规则卡片会显示审核状态、映射状态、置信度、回测命中数和样本数。
- 候选版本生成后会返回新版本 ID。

结果含义：
- `推荐数`：这个版本里有多少条交易建议。
- `规则快照`：说明该版本保存了哪些规则。
- `回测命中` / `样本数`：用于判断规则是否有稳定性。
- `已映射` 表示规则已经找到对应的可执行条件。

重要提示：
- 真正常用的策略操作入口在 `策略实验室`，不是左侧那个只显示占位内容的 `策略` 页面。

## 3.8 信号

作用：
- 查看系统生成的信号及其上下文摘要。

怎么操作：
- 按 symbol、起始日期和数量筛选。
- 点击刷新后，查看列表和右侧最新信号。

怎么看结果：
- 列表展示信号 ID、标的、方向、置信度和摘要。
- 右侧显示最新信号的完整上下文和原始 JSON。

结果含义：
- `side`：方向，常见为买入或卖出方向。
- `confidence`：置信度，越高说明系统越相信这条信号。
- `context_summary`：信号产生时的简要上下文。

## 3.9 画像

作用：
- 生成样例聚类文件，供画像和后续链路联调。

怎么操作：
- 点击 `生成样例聚类`。

怎么看结果：
- 页面会显示交易者数量、聚类数量和生成文件路径。

结果含义：
- `clusters_path`：生成出来的聚类文件路径。
- `trader_count`：参与聚类的交易者数量。
- `clusters_count`：聚类数量。

## 3.10 市场状态

作用：
- 生成 MarketState 快照，作为策略和盘前分析的输入。

怎么操作：
- 选择 `as of` 日期。
- 需要从 AkShare 拉取时，勾选 `Use AkShare`。
- 需要缓存 CSV 时，勾选 `Cache CSV`。
- 点击 `Build MarketState`。

怎么看结果：
- 页面会显示快照路径、来源和原始结构。

结果含义：
- `snapshot_path` / `market_state_path`：生成文件位置。
- `source`：数据来源。
- `Use AkShare` 打开时，表示本次优先从 AkShare 获取数据。

## 3.11 导入

作用：
- 上传交易日志，或把 crawl 状态迁移到数据库。

怎么操作：
- 选择文件后，设置来源类型。
- 如只想先看结果，保留 `Dry run`。
- 点击 `Import trade logs`。
- 如需迁移 crawl state，点击 `Migrate crawl state`。

怎么看结果：
- 导入结果会显示 rows seen、stored count、invalid、duplicates。
- 迁移结果会显示 migrated 和 skipped。

结果含义：
- `rows_seen`：读取到的原始行数。
- `stored_count`：成功写入的行数。
- `invalid`：格式不合法或无法处理的行数。
- `duplicates`：重复记录数。
- `migrated`：成功迁移的状态数。
- `skipped`：未迁移或跳过的状态数。

## 3.12 开盘

作用：
- 控制 Kaipan 的抓取、清洗和运行流程。

怎么操作：
- 设置交易日期和 slot。
- 点击 `Fetch` 抓取数据。
- 点击 `Normalize` 做标准化。
- 在右侧查看状态。
- 需要时勾选 `Start scheduler` 和 `Block`，再点击 `Run Kaipan`。

怎么看结果：
- 左侧会显示抓取结果和标准化结果。
- 右侧会显示最新 slot、raw base 和运行结果。

结果含义：
- `Fetch result`：表示本次抓取拿到了什么。
- `Normalize result`：表示本次标准化处理了什么。
- `Run result`：表示一次完整运行是否成功，以及是否启动调度器。

## 3.13 数据健康

作用：
- 快速查看系统运维摘要、失败任务、数据新鲜度、告警和追踪线索。

怎么操作：
- 打开 `数据健康` 页面。
- 点击 `Refresh dashboard` 刷新。

怎么看结果：
- `Failed jobs`：最近失败的任务。
- `Freshness`：各数据源的新鲜度。
- `Latest alerts`：最近的告警摘要。
- `Trace hints`：最近的追踪线索。
- `Worker`：当前 worker 的心跳状态。
- 下方 `Dashboard report` 会显示原始报告路径和 JSON。

结果含义：
- `critical alerts` 越多，越需要先排查。
- `stale` 说明数据太旧，需要关注数据更新链路。
- `heartbeat age` 越大，说明 worker 越久没有回报心跳。

## 3.14 回测

作用：
- 浏览回测结果，提交回测、规则验真和复现性检查任务。

怎么操作：
- 填写交易员、策略版本、日期范围和模式。
- 点击 `运行回测`、`验证规则` 或 `复现性检查`。
- 下方结果列表可按交易员和日期筛选。
- 点选一个结果，右侧查看摘要、记录、报告、验真和 JSON。

怎么看结果：
- `摘要` 页签显示交易数、有效交易、跳过交易、胜率和平均收益。
- `记录` 页签显示每条交易明细。
- `报告` 页签显示回测报告，可切换预览和原文。
- `验真` 页签显示规则验证报告。
- `JSON` 页签显示完整结构化结果。

结果含义：
- `胜率`：盈利交易占比。
- `平均收益`：单笔平均收益率。
- `有效交易`：真正参与统计的交易。
- `跳过交易`：因为条件不满足等原因没有纳入统计的交易。
- `evidence_refs`：每条记录对应的证据引用数量。

## 3.15 报告

作用：
- 查看盘前日报和盘后考核结果。

怎么操作：
- 在左侧切换 `盘前日报` 或 `盘后考核`。
- 选中日期后，在右侧查看详情。
- 可以切换 `HTML` 和 `JSON` 视图。
- 需要时点击 `刷新`。

怎么看结果：
- 盘前日报会显示报告 ID、生成时间、ideas 数量、策略版本数量、亮点和风险。
- 盘后考核会显示结果 ID、评估项数量、证据包引用、总结、失败分类、复盘说明和 ranking 特征。

结果含义：
- `ideas`：盘前产生的交易想法数量。
- `strategy_version_ids`：涉及的策略版本数量。
- `evaluations`：盘后评估条目数量。
- `evidence_pack_refs`：证据引用数量。
- `failure_categories`：失败原因分类。
- `ranking_features`：用于排序或打分的特征数据。

## 3.16 设置

作用：
- 查看、修改、校验、保存和恢复配置。

怎么操作：
- 在左侧输入配置路径，默认是 `config/app.yaml`。
- 点击 `加载`，读取该配置。
- 从分段导航里选择要修改的部分。
- 修改完成后，先点 `预览差异`。
- 确认没有问题后，再点 `保存配置`。
- 需要回退时，在备份列表里选择一个备份，点击恢复。

怎么看结果：
- 页面上会显示配置分段数量、已修改数量和备份数量。
- `预览差异` 会显示本次草稿和当前配置的变化。
- `保存` 或 `恢复` 成功后，会显示备份路径和重新加载提示。

结果含义：
- `已修改` 说明这部分配置已经被改过，还没保存。
- `配置草稿已校验` 说明当前修改可以提交。
- `备份路径` 说明保存时生成的新备份在哪里。
- `reload_message` 说明服务是否已经自动重新加载配置。
- `reload_required` / `restart_required` 若出现，说明有些配置需要重新加载或重启后才生效。

配置项怎么填写：
- `string`：直接输入文本。
- `number`：输入数字。
- `boolean`：选择 `true` 或 `false`。
- `json`：输入 JSON，例如 `{ "key": "value" }`。
- `null`：留空或写 `null`。

配置使用建议：
- 敏感值尽量通过环境变量注入，不要直接把真实密钥写入仓库。
- 如果是 JSON 段，建议只修改需要变更的字段。
- 保存前一定要先看差异，避免误改。

## 3.17 用户管理

作用：
- 管理系统用户、角色、显示名称和启用状态。

怎么操作：
- 只有 `admin` 能进入。
- 点击 `添加用户` 新建账号。
- 在用户卡片上点 `编辑` 修改信息。
- 点 `启用/禁用` 切换账号状态。
- 点 `删除` 删除用户。

怎么看结果：
- 用户卡片会显示用户名、显示名称、角色、最后登录时间和创建时间。

结果含义：
- `viewer`：只能查看。
- `operator`：可以操作和提交任务。
- `admin`：可以管理配置、用户和运维操作。
- `已禁用`：这个账号暂时不能登录。

## 3.18 运维

作用：
- 做项目级备份、恢复和回滚演练。

怎么操作：
- 点击 `开始项目备份` 创建新的项目快照。
- 需要完整回滚时，勾选 `包含处理后的数据`。
- 在备份列表里选择快照，然后输入 `RESTORE`。
- 点击 `确认恢复` 执行恢复。

怎么看结果：
- 上方会显示备份包数量、最新快照和备份根目录。
- 每个快照卡片会显示包含的表、是否包含 processed、是否复制 artifacts。

结果含义：
- `processed` 包含时，说明处理后的数据也一起备份。
- `artifacts_copied` 表示任务产物是否一起复制进备份。
- 恢复操作会覆盖数据库和 processed 目录，所以必须确认后再执行。

## 3.19 告警

作用：
- 查看告警历史，确认或解决告警，并发送测试告警。

怎么操作：
- 用状态、级别、标签和日期范围过滤。
- 选中一条告警后，可以 `确认` 或 `解决`。
- 需要测试通知链路时，点 `发送测试告警`。

怎么看结果：
- 列表会显示告警标题、ID、状态、级别、通道、时间和聚合次数。
- 右侧详情会显示告警 ID、通道、聚合数和标签。

结果含义：
- `pending` / `sent`：告警已发出，等待处理。
- `acknowledged`：已经确认，但不一定已解决。
- `resolved`：已经解决。
- `aggregated_count`：同类告警被合并了多少次。

## 4. 你最常会做的 5 个操作

### 4.1 看系统有没有问题

1. 打开 `概览`。
2. 看系统状态是否正常。
3. 打开 `任务`，看最近任务有没有失败。
4. 打开 `数据健康`，看是否有 `critical` 或 `stale`。

### 4.2 提交一个常用流程

1. 打开 `工作流`。
2. 选择流程。
3. 填表。
4. 提交。
5. 去 `任务` 看执行进度和结果。

### 4.3 找结果文件

1. 打开 `产物`。
2. 用任务 ID、来源或关键字筛选。
3. 打开详情。
4. 预览或下载。

### 4.4 调整配置

1. 打开 `设置`。
2. 加载 `config/app.yaml`。
3. 修改目标分段。
4. 先预览差异。
5. 再保存。

### 4.5 恢复出问题后的系统

1. 打开 `运维`。
2. 先创建一个当前状态备份。
3. 选择需要恢复的快照。
4. 输入 `RESTORE`。
5. 恢复后回到 `概览` 和 `任务` 复查。

## 5. 常见问题

### 5.1 页面打不开

- 先确认后端 API 是否启动。
- 再确认浏览器里的登录状态是否有效。
- 如果是配置问题，先看 `设置` 页面的配置路径是否正确。

### 5.2 任务有结果但页面看不到

- 到 `任务` 页面查看是否已经成功。
- 再到 `产物` 页面按任务 ID 过滤。
- 如果是报告类任务，再到 `报告` 页面查看对应日期。

### 5.3 配置保存失败

- 先检查是否是 `admin` 身份。
- 再检查草稿里是否有 JSON 或数字格式错误。
- 先点 `预览差异`，确认当前草稿已通过校验。

### 5.4 恢复后结果不对

- 确认选的是正确备份包。
- 确认是否包含 `processed`。
- 恢复后回到 `概览`、`任务`、`数据健康` 重新检查。

## 6. 使用建议

- 先看 `概览`，再做操作。
- 长任务完成后，先看 `任务`，再看 `产物` 和 `报告`。
- 修改 `设置` 前先备份。
- `运维` 里的恢复和回滚只给有明确权限和明确目标的人使用。
- 如果你只想先熟悉系统，建议先把 `概览`、`任务`、`工作流`、`产物`、`报告`、`设置` 这六个页面走一遍。
