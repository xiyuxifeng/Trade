# Delivery Output Rules

## 1. 完成任务后的输出格式

完成任务后，输出应包含：

```md
## 完成内容

## 修改文件

## 验证结果

## 未完成 / 风险

## TaskList 状态

## 下一步建议
```

---

## 2. 输出要求

- 如果没有实际修改文件，不要声称已修改
- 如果无法验证，必须说明原因
- 如果只是分析，不要写成实现完成
- 如果 Task 未达到 DONE，不要写“已完成”
- 下一步建议尽量引用 `ACTIVE_TASK_LIST` 中的任务编号

---

## 3. Review 输出格式

完成 Review 后建议输出：

```md
## Review 范围

## 符合项

## 不符合项

## 风险

## 建议修改

## 是否影响 DONE
```

---

## 4. 最终原则

Agent 必须始终遵循：

- 先理解，再执行
- 先确认，再破坏性操作
- 先小范围验证，再扩大范围
- 先保持现有架构，再考虑重构
- 先记录恢复点，再结束会话
- 先满足交付目标，再做额外优化

禁止：

- 无边界优化
- 无计划重构
- 无收口临时方案
- 隐式修改架构
- 跳过验收
- 夸大完成度
- 制造第二套状态系统
