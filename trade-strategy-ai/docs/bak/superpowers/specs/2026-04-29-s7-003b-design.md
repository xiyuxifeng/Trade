# S7-003b 设计：候选版本 DB 链路

> 日期：2026-04-29
> 目标：为 `optimize create-candidate` 添加 DB 持久化链路
> 前置依赖：S7-003 文件链路（已完成）、NTL-S7-000 P0 阻塞项（已修复）

---

## 1. 背景与目标

S7-003 已实现候选版本文件链路（`--db=False` 默认），轻量、无依赖、可 Git 管理。

S7-003b 在此基础上叠加 DB 链路（`--db`），将候选版本持久化到 PostgreSQL，利用数据库的索引和查询能力。

**设计原则：**
- 文件链路（`--db=False`）保持不变，作为默认链路
- DB 链路复用已有的 `StrategyLibraryService.create_candidate_version()`
- 双链路并存，通过 CLI 参数切换，不相互干扰

---

## 2. 现状

| 组件 | 状态 | 说明 |
|------|------|------|
| `StrategyVersion` schema | ✅ 有 version_type + parent_version_id | `StrategyVersionType` enum（manual/candidate） |
| `TraderStrategyVersion` ORM | ❌ 缺少两列 | 当前只有 `strategy_payload` JSONB |
| `StrategyLibraryService.create_candidate_version()` | ✅ 已实现 | 接收 parent_version_id + adjustments |
| `StrategyLibraryRepository._to_orm_model()` | ❌ 未映射新列 | 新列无法持久化 |
| `cli/optimize create-candidate` | ✅ 文件链路 | `--db` 参数不存在 |

---

## 3. 架构设计

### 3.1 DB Schema 变更

在 `trader_strategy_versions` 表新增两列：

```sql
ALTER TABLE trader_strategy_versions ADD COLUMN version_type VARCHAR(32) NOT NULL DEFAULT 'manual';
ALTER TABLE trader_strategy_versions ADD COLUMN parent_version_id VARCHAR(256);
```

- `version_type`：版本类型，`manual`（手动创建）或 `candidate`（优化流程生成）
- `parent_version_id`：父版本 ID，用于候选版本追溯正式版本（仅 candidate 版本有值）

**Migration 兼容性：**
- 已有记录 `version_type` 默认 `manual`，`parent_version_id` 默认 `NULL`
- 符合已有数据的预期（已有记录都是手动创建的正式版本）

**索引扩展：**
- 在 `version_type` 列建索引，支持按类型快速过滤候选版本
- 在 `(trader_id, strategy_date, status)` 已有索引基础上，DB 可高效执行"取某日最新 released 版本"查询

### 3.2 ORM Model 变更

文件：`src/models/trader_strategy_version.py`

新增两个 mapped column：

```python
version_type: Mapped[str] = mapped_column(
    String(32), nullable=False, default="manual"
)
parent_version_id: Mapped[str | None] = mapped_column(String(256), nullable=True)
```

### 3.3 Repository 变更

文件：`src/strategy_library/repository.py`

更新三个方法：

**`_to_orm_model()`**：写入新列
```python
orm_obj.version_type = version.version_type.value  # manual 或 candidate
orm_obj.parent_version_id = version.parent_version_id
```

**`_from_orm_model()`**：读取新列，缺失时兼容
```python
version_type = StrategyVersionType(getattr(orm_obj, 'version_type', 'manual') or 'manual')
parent_version_id = getattr(orm_obj, 'parent_version_id', None)
```

**`_update_existing()`**：更新时同步两列

### 3.4 CLI 变更

文件：`cli/optimize.py`

**新增参数：**

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `--db` | bool | `False` | 启用 DB 链路（默认文件链路） |
| `--trader` | str | `""` | trader_id（`--db=True` 时必需） |
| `--date` | str | `""` | 策略日期 YYYY-MM-DD（`--db=True` 时必需） |

**`--db=False`（默认，文件链路）：**
- 行为与现有 S7-003 完全一致
- 从 `--parent` JSON 文件加载正式版本
- 候选版本写入 `--output` JSON 文件

**`--db=True`（DB 链路）：**
1. 按 `trader_id + strategy_date` 从 DB 加载最新的 `released` 版本（利用唯一索引约束）
2. 从该正式版本的 `rules_snapshot` 应用调整建议，生成候选版本
3. 调用 `StrategyLibraryService.create_candidate_version()` 写入 DB（status=draft）
4. 如果指定了 `--output`，同时写 JSON 文件（`--output` 参数与链路模式解耦）

**关键逻辑：**

```python
if db:
    # DB 链路：按 trader_id + date 从 DB 取 released 版本
    from src.strategy_library.service import StrategyLibraryService
    svc = StrategyLibraryService()
    async with get_session_factory() as session:
        released_versions = await svc._repo.get_released_by_trader_and_date(
            session=session,
            trader_id=trader,
            strategy_date=date.fromisoformat(date_str),
        )
        if not released_versions:
            typer.secho(f"未找到正式版本: trader={trader}, date={date_str}", fg=typer.colors.RED)
            return
        parent_version = released_versions[0]  # 唯一 released 版本
        # 调用 create_candidate_version 写 DB
        candidate = await svc.create_candidate_version(...)
else:
    # 文件链路：现有逻辑不变
    ...
```

## 4. 双链路行为对照

| 场景 | `--db=False`（默认） | `--db=True` |
|------|---------------------|-------------|
| 父版本来源 | `--parent` JSON 文件 | DB 查询（trader_id + strategy_date） |
| 候选版本输出 | `--output` JSON 文件 | DB 持久化 + 可选 JSON 文件（`--output`） |
| DB 依赖 | 无 | 需要 PostgreSQL 连接 |
| 适用场景 | 轻量验证 / 版本对比 | 正式生产流程 |
