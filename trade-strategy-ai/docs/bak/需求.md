# 需求

## 一、最终目标

构建一个能够通过学习交易员文章、评论与交易行为，持续沉淀策略知识，并在市场快照基础上主动生成候选池、盘前建议、盘后归因、离线回测和持续优化的交易系统。

系统最终要实现：

1. 学习：持续学习交易员文章、评论、交易记录。
2. 理解：把这些信息沉淀为可追溯、可聚合的策略知识。
3. 决策：按 `trader_id` 输出独立策略版本和盘前建议。
4. 评估：盘后统一评分、归因和记忆写回。
5. 优化：通过回测和赛马持续筛选 trader、规则和策略版本。

---

## 二、核心业务需求

### 1. 数据需求

系统需要持续获取并管理以下数据：

- 交易员文章与评论
- 交易记录
- 个股、指数、板块日线数据
- 热点、题材、竞价、涨停、龙虎榜等市场快照
- 盘后解释所需事件型数据

### 2. 策略知识需求

系统需要把文章和行为信息转成可被系统消费的结构化知识，包括：

- `strategy_rules`
- `preconditions`
- `trading_symbols`
- trader 风格偏好与风险偏好
- 每日 per-trader 策略版本

### 3. 盘前需求

系统盘前需要能够：

- 读取最新市场快照
- 生成 `hot_topics`
- 解析 `topic_constituents`
- 筛选 `strong_symbols`
- 为每个 trader 结合画像、记忆和策略版本生成结构化建议

### 4. 盘后需求

系统盘后需要能够：

- 基于统一口径对建议评分
- 生成 ranking
- 生成 Evidence Pack
- 对差评进行结构化 postmortem
- 把复盘结果写回 TraderMemory

### 5. 回测与优化需求

系统需要能够：

- 基于相同快照和评分口径做离线回测
- 验证 LLM 规则是否真的可程序化和有效
- 对 trader、规则和版本做持续优化

## 三、架构需求

### 1. 保留为 Agent 的角色

- `ManagerAgent`
- `DataAgent`
- `TraderAgent`
- `StrategyAgent`
- `RiskAgent`

这些角色保留的原因是：它们承担稳定的流程角色和清晰的对外输入输出。

### 2. 降级为 module/service 的能力

- `KnowledgeAgent` -> `article_metadata` 抽取链路 + `strategy_library`
- `BehaviorAgent` -> `trader_profile` + `evaluation` + `backtest`
- `BacktestAgent` -> `src/backtest`

这些能力更适合作为确定性模块，而不是继续扩展成独立主线 Agent。

### 3. 冻结或退出主线的能力

- `AlignmentAgent`

旧“文章策略 vs 行为对齐”方向仍可保留研究价值，但当前不再是主线交付目标。

---

## 四、非功能需求

- 不自动下单。
- 运行支持 CLI 手动触发和服务化定时触发。
- 所有关键中间结果优先落快照或落库，保证可回放。
- 私有接口必须先通过 provider 隔离，不直接耦合主链路。
- 所有关键能力必须具备可追溯、可解释和可验证性。

---

## 五、当前阶段的实现边界

当前阶段优先实现：

- 数据资产层
- provider 层
- 市场候选池
- 策略版本库
- 盘前主链路升级
- 盘后评分与归因
- 回测与规则验真

当前阶段不优先实现：

- 自动交易
- 分钟级复杂回测
- UI 管理后台
- 把所有旧 Agent 都继续当作核心主线推进
