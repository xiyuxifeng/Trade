# 重构 TaskList Review 结论

## Review 范围

本次 Review 对照了前期已经确认的产品和技术决策：

- 文章到规则、回测、画像、策略、盘前、盘后完整闭环。
- “Regime”面向用户统一翻译为“市场状态”。
- 作者画像不是用户画像，也不是作者实盘画像。
- 作者画像由 LLM 内容理解、规则结构统计和回测验证共同生成。
- 100+ 篇文章采用逐篇结构化、去重聚类、批次汇总和增量更新。
- OHLCV 是回测底座。
- Kaipan 是盘前盘后和短线市场上下文。
- 正式策略低频版本化更新。
- 每日自动生成规则选择、策略实例和盘前计划。
- 盘后分别生成规则、作者画像和策略建议。
- 最终 Web 必须面向普通用户，而不是开发人员。

- 允许 AI 修改 UI、前端、后端和数据库：已明确。

- 任务粒度不过细：采用 Stage + 每阶段少量任务。
- Prompt 更新任务写入 TaskList：已写入 Stage 3。

- 面向用户而非开发：已写入产品原则和最终验收。
- 页面可加入简短说明：已明确允许并要求必要时添加。
- 数据、规则、画像和策略可追溯：已覆盖。
- 不建立第二套正式事实源：已明确禁止。
- 旧入口有退役阶段：已覆盖 Stage 12。

## 需要实施时注意

1. TaskList 允许较大范围修改，但每次仍应按 Stage 执行，避免同时改动所有模块。
2. Stage 0 的审计和迁移矩阵不能跳过。
3. Prompt 新版本应先用固定文章集对照验证。
4. 数据库迁移必须提供安全重跑和失败恢复。
5. UI 视觉风格可以重做，但用户流程和业务语言优先于视觉效果。
6. 旧系统在迁移完成前可作为兼容层，但不能继续承载新功能。

## Review 结论

当前 TaskList 可以作为 AI 重构主执行文档使用，未发现与前期讨论相冲突的核心问题。


## 第二轮 Review：规则审核机制

已补充自动审核与人工审核 UI，Review 结论如下：

- 不能完全取消人工审核，因为规则可能包含 LLM 过度推断、模糊条件、错误参数和错误泛化。
- 不需要人工逐条审核全部规则，低风险规则可通过确定性自动审核批量进入待回测。
- 自动审核通过不等于正式可用；正式策略入选前必须人工确认。
- 审核状态、原因、修改内容和审核人必须可追溯。
- Prompt、自动审核、回测验证和正式审批职责已明确分离。

## 本轮额外优化

Review 后新增或强化：

1. 自动审核状态枚举和中文映射。
2. 自动审核应以确定性规则为主，避免使用第二个自由 LLM 做最终裁决。
3. 规则风险等级，用于决定是否必须人工审核。
4. 低风险规则批量处理，降低 100+ 篇文章的人工成本。
5. 正式策略入选前的二次人工确认。
6. 审核审计记录，包括修改前后内容。
7. 可回测状态与正式可用状态分离。
8. 自动审核阈值应由系统配置管理，并在 UI 中说明影响。

## 仍建议在实现时补充

- 建立固定审核样本集，衡量自动审核的误通过率和误拦截率。
- 为自动审核规则提供版本号，避免阈值变化导致结果不可复现。
- 记录自动审核版本与规则版本的关联。
- 审核 UI 支持键盘快捷操作和批量处理，以降低大规模文章审核成本。

当前文档体系在补充以上机制后更加完整，没有发现新的核心流程冲突。


## 第三轮 Review：执行保障与样本集

本轮确认黄金样本集不是启动重构的前置阻塞项。

已补充：

1. Stage 3 自动从现有文章建立候选回归样本。
2. 用户只需快速确认，无需手工整理全部样本。
3. 固定回归样本通过前禁止全量重跑 100+ 篇文章。
4. 每个 Stage 增加出口条件。
5. 增加统一运行 ID 和可观测性要求。
6. 增加 LLM 与回测成本控制。
7. 增加数据可用时间语义，降低未来数据泄漏风险。
8. 增加灰度迁移与回滚策略。

Review 结论：

- 当前 TaskList 已覆盖重构成功所需的主要产品、技术、数据、迁移和验收约束。
- 没有发现必须继续扩展的新核心方向。
- 后续更重要的是按 Stage 执行和验收，不建议继续增加大范围规划内容。


## 第四轮 Review：Prompt 完整性、调用编排与退役

本轮补齐：

- `concept_extraction_v1.md`
- `llm_attribution_v1.md`
- `article_analysis_v1.md`
- `article_analysis_repair_v1.md`
- `LLM-Prompt-Orchestration.md`

确认后的生产调用方式：

- 单篇普通文章通常一次统一主调用。
- Schema 或局部内容失败时最多一次定向修复。
- 作者画像按批次或事件调用，不逐篇调用。
- 盘后归因仅在低置信度、证据冲突或重要信号时调用。
- 普通信号摘要优先使用程序模板，必要时调用 LLM。

旧 Prompt 删除已经纳入 Stage 3 的正式任务和验收。

只有新调用链完成、固定样本与批量验证通过、历史结果可读、所有引用清除、观察期和回滚验证完成后，才允许彻底删除旧 Prompt。

Review 结论：

- Prompt 套件和调用方式已经完整。
- 不存在已知缺失的旧核心 Prompt 替代项。
- Stage 3 的完成标准已明确包含旧 Prompt 正式退役和删除。
