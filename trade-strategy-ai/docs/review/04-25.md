## 1. 整体评估

结论：Stage 5 的主链路已搭建完整（EvidencePack → 评分 → ranking → 记忆写回），但存在关键字段对齐与口径一致性问题，导致盘后评估在真实 A 股场景中容易退化为“fallback/空数据”的结果，排名与记忆写回的质量会显著受影响。需要先修复数据口径与字段映射，再做进一步优化。

## 2. 关键问题（按严重度）

### P0（影响核心正确性）

1) EvidencePack 的行情字段与评估逻辑不一致，导致 MFE/MAE/return_pct 基本无法生效。✅
- EvidencePack 侧从 DataAgent 拉取的是 ohlcv_1d，但评估逻辑只读取 market_data["bars"]，结果大多为空，直接进入 fallback。[src/agents/manager_agent/agent.py](src/agents/manager_agent/agent.py#L256-L269) [src/agents/manager_agent/agent.py](src/agents/manager_agent/agent.py#L763-L779) [src/agents/data_agent/skills/fetch_ohlcv.py](src/agents/data_agent/skills/fetch_ohlcv.py#L25-L68) [src/evaluation/postmortem_service.py](src/evaluation/postmortem_service.py#L154-L170)
- 建议：统一 MarketDataSnapshot 结构，显式把 ohlcv_1d 映射为 bars（例如 market_data["bars"] = ohlcv_1d[symbol]），并在 EvidencePack 生成时固定字段名。

2) return_pct 口径混用“百分比”和“比例”，导致阈值判断与排名不稳定。✅
- compute_mfe_mae_return 返回百分比（*100），fallback 却返回比例；配置注释也按比例理解。 [src/evaluation/metrics_calculator.py](src/evaluation/metrics_calculator.py#L92-L104) [src/agents/manager_agent/agent.py](src/agents/manager_agent/agent.py#L777-L783) [config/app.yaml](config/app.yaml#L26-L33)
- 结果：同一 idea 在有 bars 与无 bars 时评估口径不同，min_expected_return 判定失真。
- 建议：统一 return_pct 口径（建议比例或百分比二选一），同步 config 注释、评估、ranking 与测试。

### P1（影响功能正确性或数据一致性）

3) build_topic_tags 调用参数错误，导致主题标签无法写入记忆。✅
- build_topic_tags 期望 list[str]，但传入了 TradeIdea 对象。 [src/market_universe/topic_utils.py](src/market_universe/topic_utils.py#L13-L33) [src/agents/manager_agent/agent.py](src/agents/manager_agent/agent.py#L836-L839)
- 建议：传入 idea.source_topic_ids；并为 None/空列表补充兜底路径。

4) RankingRepository.upsert 删除条件缺少 trader_id，可能误删其他交易员的记录。✅
- Unique key 包含 trader_id，但 delete 只按 trade_date/version/symbol。 [src/models/ranking_entry.py](src/models/ranking_entry.py#L21-L33) [src/evaluation/ranking_repository.py](src/evaluation/ranking_repository.py#L33-L55)
- 建议：delete 条件补充 trader_id，或使用 ON CONFLICT(trade_date, trader_id, strategy_version_id, symbol) upsert。

5) postmortem_tasks 的 fallback EvidencePack 只有 last_price，但 PostmortemService 不会用它。✅
- PostmortemService 只读 bars，bars 为空时 return_pct 恒为 0。 [src/pipeline/tasks/postmortem_tasks.py](src/pipeline/tasks/postmortem_tasks.py#L76-L140) [src/evaluation/postmortem_service.py](src/evaluation/postmortem_service.py#L154-L176)
- 建议：fallback 时把 last_price 映射为 bars（或在 PostmortemService 内部对 last_price 做降级计算）。

### P2（一致性/可维护性问题）

6) EvidencePack.strategy_version_snapshot 的 default_factory 用了 dict，类型不匹配。✅
- 该字段应为 list[dict]。 [src/evaluation/evidence_pack.py](src/evaluation/evidence_pack.py#L60-L65)

7) LLM 归因 prompt 字段与 TradeIdea 实际字段不一致，可能导致 LLM 输入缺失。✅
- 模板填充使用 target/stop_loss，但 TradeIdea 是 target_price/stop_loss_price。 [src/evaluation/postmortem_service.py](src/evaluation/postmortem_service.py#L309-L337)

8) Postmortem 的 strategy_version_id 为空字符串与 __none__ 混用。✅
- add_entry_from_metrics 统一用 __none__，但 add_entry 仍用空字符串。 [src/evaluation/ranking_service.py](src/evaluation/ranking_service.py#L129-L140) [src/evaluation/ranking_service.py](src/evaluation/ranking_service.py#L190-L206)
- 建议：统一用 __none__，避免版本分组与 unique key 不一致。

## 3. 按检查点逐项评审

### 3.1 子任务实现与数据流是否符合真实市场情形
- ✅ 主流程符合设计闭环，但“行情字段 → 评估指标”未对齐，导致盘后评分在真实行情中失效。[src/agents/manager_agent/agent.py](src/agents/manager_agent/agent.py#L763-L779) [src/evaluation/postmortem_service.py](src/evaluation/postmortem_service.py#L154-L176)
  - 已修复内容：`ManagerAgent` 已将 `ohlcv_1d` 映射到 `market_data["bars"]` 并补齐 `entry_price/target_price/stop_loss_price`，避免评估侧空数据退化。
- ❌ A股交易规则缺口：T+1 不能当日卖出、涨跌停限制（10%/20%/ST 5%）未在 exit 判定中体现，可能高估止盈/止损触发概率。
  - 未修复原因：该项会改变评估业务语义，需先明确规则口径（主板/创业板/ST）与回放验收标准，超出本次“字段对齐与口径统一”修复范围。
  - 建议：在 `metrics_calculator` 增加可配置交易约束层（`t_plus_one`, `limit_up_down_policy`, `board_type`），并补充按市场分层的回归测试样例。

### 3.2 代码逻辑是否正确、是否存在不合理规则
- ✅ return_pct 口径混用导致回测评价不一致，属于核心逻辑问题（见 P0-2）。
  - 已修复内容：`compute_mfe_mae_return` 已统一为比例口径（`0.01=1%`），与 fallback / config 口径一致。
- ✅ Ranking upsert 删除条件遗漏 trader_id 可能引发跨交易员数据污染（见 P1-4）。
  - 已修复内容：`RankingRepository.upsert` 删除条件已补 `trader_id`。

### 3.3 是否有遗漏情况或边界条件
- ✅ bars 空/缺失时的降级路径只在 ManagerAgent 生效，postmortem_task 未覆盖（见 P1-5）。
  - 已修复内容：`postmortem_tasks` fallback 已把 `last_price` 映射为单日 `bars` 并补齐关键价格字段。
- ❌ 交易日停牌/无成交量 bar 未识别；建议增加“无成交/停牌”识别，避免 MFE/MAE 误判。
  - 未修复原因：当前 provider 返回格式未统一给出“停牌/无成交”标准标识，直接硬编码规则风险较高。
  - 建议：先定义统一 bar 质量标志（如 `is_halted`、`has_trade`、`volume==0` 语义），再在评估时跳过/降权并记录状态。

### 3.4 是否有可优化的地方或更合理实现方式
- ❌ 建议定义统一的 MarketDataSnapshot schema（bars/ohlcv_1d/indicators/entry_price/target/stop_loss），并在 EvidencePack 生成阶段完成格式化，避免多处逻辑分支。
  - 未修复原因：本次仅做最小可用修复（字段对齐），尚未完成 schema 抽象与跨模块收敛。
  - 建议：新增 `MarketDataSnapshot` 模型并集中在 EvidencePack 工厂层做标准化，减少下游分支判断。
- ❌ postmortem_tasks 通过遍历文件目录找 pack_id，复杂度 O(n^2)，可建立索引或直接用 idea_id 作为文件名映射。
  - 未修复原因：当前数据规模下正确性优先，性能问题未到阻塞级别。
  - 建议：改为 `idea_id -> pack_id` 索引文件或直接以 `idea_id` 命名证据包，任务侧 O(1) 查询。

### 3.5 是否有不必要的复杂性或冗余代码

  - 已修复内容：新增 `compute_return_pct()` 公共函数，`compute_mfe_mae_return()` 与 `ManagerAgent` fallback 已复用同一实现，避免口径漂移。

## 4. 建议优先级与修复顺序

当前已修复的 P0/P1 项见上文。后续仍建议按以下顺序推进未修复项：

1) 增加 A股规则约束（T+1、涨跌停）并完善停牌/无成交边界。
