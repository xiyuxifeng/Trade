## 二、逐项检查

### 1. 代码是否符合设计目标，是否存在不合理的地方

**✅ 符合的部分：**

- `src/backtest/` 模块独立，职责边界清晰（schema / execution / scoring / engine / reporting / rule_registry / reproducibility）
- `score_backtest_trade` 直接委托给 `compute_mfe_mae_return`，不复制公式，复用策略正确
- `BacktestEngine` 编排路径 `SnapshotLoader → StrategyReplayer → Scoring → BacktestResult` 清晰
- CLI 三个子命令（`run` / `validate-rules` / `reproducibility-check`）覆盖主要场景
- `RuleMeta` / `classify_rule` 实现了规则可程序化分类的基本能力
- ST 规则日期切换（沪市 2026-07-06 从 5% 调为 10%）已实装，符合 A 股规则演变

**❌ 不符合或存在问题的部分：**

#### 1.1 `snapshot_loader.py` 只能加载一种 snapshot slot

代码第 72 行硬编码为：
```python
market_universe = await self.snapshot_service.load(
    trade_date.isoformat(), slot="market_universe"
)
```

但根据 Stage 0/2 的设计，快照有三种独立类型（`hot_topics_snapshot` / `topic_constituents_snapshot` / `strong_symbols_snapshot`），应分别加载。`load_market_context` 目前只加载了 `market_universe`，其他两种 topic 快照被忽略。

#### 1.2 `engine.py` 第 282 行 bug

```python
exit_date_str = score_result.get("exit_date")
if exit_date_str and bars:
    for bar in bars:
        if str(bar.get("date")) == exit_date_str:  # ← bar.get("date") 已是字符串
            exit_price = bar.get("close")
```

`bar.get("date")` 返回的已经是字符串，`str()` 包装是冗余的。但真正的问题在于：当 `score_result["exit_date"]` 是 `None`（未出场）时，`BacktestTradeRecord.exit_date` 接受 `date | None = None`，传入 `None` 是合法的，不算 bug，只是语义上"未出场日"传了 `None`。

#### 1.3 `engine.py` 第 16 行假性导入

```python
from src.backtest.rule_registry import RuleMeta  # 导入了但没用到
from src.backtest.scoring import score_backtest_trade  # 在 TYPE_CHECKING 下
```

#### 1.4 `validate_rules_for_trader` 函数名和实现不匹配

函数签名是 `validate_rules_for_trader`，但 engine.py 中的主函数是 `validate_rule_hits`（单数），两者关系不清晰。

#### 1.5 `cli/backtest.py` 中 `SnapshotLoader()` 无参数注入

```python
loader = SnapshotLoader()  # strategy_repo=None, snapshot_service=None
```

这导致 `load_version_for_date` 永远返回 `None`，所有回测日都会返回 `skipped`（no_strategy_version）。CLI 层面没有提供快照服务或策略库注入的入口，实际运行会全部 skip。

### 2. 是否存在代码缺陷或者设计缺陷

#### 2.1 严重：CLI `backtest run` 实际无法运行

`BacktestEngine` 的 `loader` 和 `strategy_loader` 均为 `None` 时，所有交易日都返回 `skipped(no_loader_configured)` 或 `skipped(no_strategy_loader)`。CLI 层面没有注入任何真实依赖，导致回测命令无法产生有效交易记录。

**建议**：CLI 应支持传入 db url 或提供默认的 loader/strategy_loader 注入。

#### 2.2 中等：`iter_trade_dates` 返回 `list[date]` 而非生成器

```python
def iter_trade_dates(date_from: date, date_to: date) -> list[date]:
    result = []
    ...
    return result
```

虽然对回测场景影响不大（回测日期区间不会特别大），但与函数名"iter"（通常指 iterator/generator）语义不符，调用者可能误用为无限迭代器。

#### 2.3 中等：规则验真 CLI 命令名错误

```python
@app.command("validate-rules")  # ←typer 命令名为 validate-rules（含连字符）
@app.command("reproducibility-check")  # ←含连字符
```

但 plan 文件中记录的命令名是 `validate_rules` / `reproducibility-check`，实际 Typer 注册的是带连字符版本，与 plan 描述略有出入（但实际功能正常）。

#### 2.4 轻微：`execution.py` 的 `replay_candidates` 不使用 `market_context`

```python
def replay_candidates(
    version: StrategyVersion, market_context: dict[str, Any]
) -> list[dict[str, Any]]:
    return [...]  # market_context 未被使用
```

参数存在但函数体内完全没有引用，是死参数。这是设计选择（只做格式转换），但应加 `_` 或在 docstring 说明"为未来扩展预留"。

#### 2.5 轻微：`rule_registry.py` 的指标分类依赖手工关键词

`PROGRAMMABLE_INDICATORS` 和 `INDICATOR_PATTERNS` 是硬编码字典，新增指标需要手动扩展，容易遗漏。新规则可能因为没有对应模式而被错误归类为 `unsupported`。

### 3. 和之前 Stage 任务的代码之间是否可以正常串联，数据是否可以正常传递

`score_backtest_trade` → `compute_mfe_mae_return` → `compute_return_pct`，完全复用 Stage 5 评分口径，7 个返回值（mfe/mae/return_pct/exit_triggered/exit_date/halted_dates/eval_date）对齐一致。

#### 3.2 ✅ `rules_snapshot` 串联：已验证

根据 TaskList 记录和 plan 中的预检结果，`rules_snapshot` 在 `repository.py:117` 写入、在 `service.py:137` 发布时保留、在 `repository.py:148` 读回，链路打通。

#### 3.3 ⚠️ `SignalVersioning` 数据串联：部分完成但未使用

`engine.py` 第 197-206 行对 `mode == "rule_validation"` 直接返回 `skipped`，没有实际执行规则验真逻辑。`validate_rules_for_trader` 函数存在但需要通过 CLI 显式调用，不是 `BacktestEngine.run` 的一部分。

**建议**：CLI 应在 `run_backtest` 中创建 `StrategyLibraryRepository`（传入 db session）并注入到 `SnapshotLoader`。

### 4. 是否符合 A 股市场的实际情况

#### 4.1 ✅ T+1 规则：已实现

`compute_mfe_mae_return` 第 340-347 行实现了 T+1 约束，entry_date 当日不检查止盈止损，只累计 MFE/MAE。

#### 4.2 ✅ 涨跌停限制：已实现

`compute_mfe_mae_return` 第 329-338 行计算 effective_high / effective_low，止盈用 min(high, limit_up_price)，止损用 max(low, limit_down_price)。

#### 4.3 ✅ 停牌识别：已实现

`_is_bar_halted` 实现了双重规则（显式 `is_halted` + volume==0 且价格无波动），避免停牌日价格影响 MFE/MAE。

#### 4.4 ✅ ST 规则日期切换：已实现

`_get_limit_pct` 第 108-114 行区分沪市/深市 ST，2026-07-06 起沪市 ST 从 5% 调整为 10%，深市 ST 维持 5%。

#### 4.5 ⚠️ 一字涨停/跌停无法成交：未区分

代码只限制了止盈止损价格不能超出涨跌停范围，但没有区分"一字涨停能否实际买入"和"盘中曾开板是否可以买入"。按 TaskList 备注中提到的规则："一字涨停板无法买入成交，除非盘中开板，如果买入的话可以按涨停价格计算"——当前实现没有区分"开板"情况。

#### 4.6 ⚠️ 开盘价申报价格限制：未实现

根据 TaskList 备注 4："如果以开盘价格买入和卖出需要按照这个规则计算成交价: A股市场沪深主板、科创板、创业板的限价申报价格不得高于基准价格的 102% 且不得低于 98%"——`compute_mfe_mae_return` 中以收盘价作为实际成交价处理，没有考虑限价申报 98%-102% 的约束。

#### 4.7 ✅ 交易日判断：仅跳过周末

`is_trade_date` 只排除了周六(5)和周日(6)，未排除法定节假日。这在回测短期区间（几周内）影响不大，但跨月度回测可能包含假节日。
