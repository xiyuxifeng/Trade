# 管理员运维指南

本文档面向管理员。普通业务用户不需要把本指南作为日常流程。

## 管理边界

管理员可以处理：

- 配置和权限。
- 数据状态和调度。
- 运行记录和告警。
- 系统健康。
- 数据库迁移。
- 备份和恢复。
- 审计和回滚。

管理员不能绕过正式治理路径：

- 不能直接把未审核规则发布为正式规则。
- 不能直接覆盖作者画像。
- 不能直接覆盖正式策略。
- 不能用单日盘后结果修改正式资产。
- 不能把缺失或冲突状态改成成功。

## 系统管理入口

正式入口：

- `系统管理` → `系统状态`
- `系统管理` → `配置管理`
- `系统管理` → `数据与调度`
- `系统管理` → `运行与告警`
- `系统管理` → `权限与审计`
- `系统管理` → `用户管理`
- `系统管理` → `系统健康`
- `系统管理` → `数据库迁移`
- `系统管理` → `备份恢复`

历史入口已经迁移到这些正式入口。普通用户不应使用历史入口作为日常路径。

## 日常检查

管理员每天应检查：

- 数据是否按交易日更新。
- 盘前数据是否在开盘前可用。
- 收盘后数据是否在复盘前可用。
- 当前正式策略是否存在且可用。
- 是否有失败、降级、冲突或无权限错误。
- 备份是否按计划生成。

## 数据与调度

管理员要做什么：

- 查看历史行情覆盖范围。
- 查看盘前和盘后数据可用时间。
- 查看市场状态计算结果。
- 对缺失数据执行明确补齐动作。

系统会做什么：

- 展示数据版本、覆盖率、质量状态和影响范围。
- 记录补齐动作和结果。

输出结果：

- 可用于回测和每日计划的数据状态。

处理原则：

- 缺失数据保持不可用或部分状态。
- 补齐动作必须可重试。
- 不使用实时数据替代固定回测数据。

## 运行与告警

管理员要做什么：

- 查看失败原因。
- 识别影响范围。
- 对可恢复处理执行重试或恢复。

系统会做什么：

- 展示运行步骤、耗时、错误分类和恢复建议。
- 保留失败证据。

输出结果：

- 修复后的运行状态。
- 仍需人工处理的事项。

处理原则：

- 先看业务影响，再看技术细节。
- 不删除失败证据来制造成功状态。
- 重试前确认输入数据和配置没有冲突。

## 规则池批量回测运维

管理员要做什么：

- 确认批量回测只从 `规则与回测` → `回测实验` 发起。
- 建议普通设备每批 20 到 50 条规则，避免单次运行时间过长。
- 查看批次计划、运行记录、失败原因和合并状态。
- 对失败批次先修复数据或配置，再让用户重新启动该批次。

系统会做什么：

- 保存批次计划、每批规则清单、运行记录引用和合并结果引用。
- 只在所有批次完成且参数一致时合并结果。
- 如果批次失败、缺少结果或参数冲突，保持部分或冲突状态，并提示影响范围。

处理原则：

- 不启用自动暂停、自动恢复或并行执行。
- 不把失败批次排除后伪装为完整成功。
- 不绕过正式回测入口直接写入合并结果。

## 数据库迁移

管理员要做什么：

- 升级前备份数据库。
- 执行迁移前检查当前版本。
- 执行迁移后确认版本和核心页面可用。

建议命令：

```bash
python -m alembic -c src/db/migrations/alembic.ini current
python -m cli.main db-migrate --config config/app.template.yaml
python -m alembic -c src/db/migrations/alembic.ini current
```

系统会做什么：

- 执行迁移链。
- 保留迁移版本记录。

失败处理：

- 停止后续发布。
- 保留错误输出。
- 从备份恢复或按迁移说明修复。
- 不手工改表绕过迁移。

## 备份与恢复

管理员要做什么：

- 按计划生成备份。
- 升级和高风险操作前手工确认备份可用。
- 恢复前确认恢复范围和影响。

系统会做什么：

- 记录备份清单。
- 恢复时保留审计记录。

处理原则：

- 恢复是高风险操作，应有明确授权。
- 恢复后检查首页、系统状态、策略中心、每日盘前和每日盘后。
- 恢复不能绕过规则、画像和策略治理。

## 权限与审计

管理员要做什么：

- 为普通用户授予业务页面权限。
- 为维护人员授予系统管理权限。
- 定期查看高风险操作记录。

系统会做什么：

- 按角色控制页面和动作。
- 记录关键操作。

处理原则：

- 不共用管理员账号。
- 不把管理员诊断页面作为普通用户日常流程。

## 常见故障

### 首页显示数据不可用

影响：

- 普通用户无法生成可信盘前计划或盘后复盘。

处理：

- 进入 `系统管理` → `数据与调度` 查看缺失范围。
- 补齐数据后让用户重新生成。

### 盘前计划生成失败

影响：

- 今日计划不可用。

处理：

- 检查当前正式策略是否存在。
- 检查市场状态和规则适用性。
- 检查数据是否过期或冲突。

### 盘后复盘生成失败

影响：

- 今日归因和优化建议不可用。

处理：

- 检查今日盘前计划是否存在。
- 检查收盘后实际数据是否可用。
- 检查数据版本是否匹配。

### 策略无法发布

影响：

- 每日盘前不能使用新的候选策略。

处理：

- 检查规则、回测、适用性和画像证据。
- 对样本不足或数据缺失保持观察。
- 不跳过验证强行发布。

## 升级和回滚

升级前：

- 确认工作区干净。
- 备份数据库和运行配置。
- 记录当前版本。
- 执行迁移检查。

升级后：

- 检查健康状态。
- 检查正式导航。
- 检查首页、研究中心、规则与回测、作者画像、策略中心、每日交易。

回滚时：

- 先恢复代码版本。
- 再按备份策略恢复数据。
- 检查审计记录。
- 确认回滚不会丢失已发布规则、画像、策略和每日计划证据。
