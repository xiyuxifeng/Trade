# 部署与运行手册

本文档面向部署者和管理员，不面向普通业务用户。它只说明如何部署和运行当前正式系统，不定义新的架构事实源。

## 1. 运行环境要求

后端：

- Python 3.11 或项目当前锁定的兼容版本。
- PostgreSQL。
- Alembic 迁移工具。
- 可访问项目依赖包源。

前端：

- Node.js 18。
- pnpm。
- 浏览器自动化运行时仅用于验收测试，不是普通运行必需项。

浏览器验收：

- Playwright。
- Chromium 运行时。
- 仅在执行浏览器验收时安装和使用。

## 2. 配置来源和安全原则

配置来源：

- 模板配置：`config/app.template.yaml`。
- 当前环境变量：数据库连接、管理员访问密钥、外部服务凭据、运行端口。
- 部署平台配置：服务端口、进程管理、日志目录和反向代理。

安全原则：

- 真实凭据只放在部署环境或受控密钥系统。
- 不把真实凭据写入仓库。
- 不把本机绝对路径写入正式文档或提交记录。
- 日志和检查命令只能输出脱敏状态。
- 配置模板可以提交，真实运行配置不能提交。

## 3. 数据库初始化、迁移和检查

部署者要做什么：

- 创建数据库。
- 注入数据库连接。
- 执行连接检查。
- 执行迁移。
- 确认迁移版本。

建议命令：

```bash
python -m scripts.web_local env-check
python -m cli.main db-check --config config/app.template.yaml
python -m cli.main db-migrate --config config/app.template.yaml
python -m alembic -c src/db/migrations/alembic.ini current
```

预期结果：

- 环境检查只显示脱敏状态。
- 数据库连接成功。
- 迁移位于当前仓库迁移链。

失败处理：

- 数据库不可连接：检查连接、网络、权限和数据库服务。
- 迁移失败：停止发布，保留错误输出，先恢复备份或修复迁移问题。
- 版本不一致：不要手工改迁移记录，按迁移链修复。

## 4. Web 前端构建与运行

部署者要做什么：

- 安装前端依赖。
- 运行类型检查。
- 构建静态资源。

建议命令：

```bash
cd web
pnpm install
pnpm typecheck
pnpm build
```

输出结果：

- 前端构建产物。
- 可由后端或静态服务托管的正式页面。

失败处理：

- Node 版本不兼容：切换到 Node.js 18。
- 依赖安装失败：检查网络和包源。
- 类型检查失败：停止发布，修复前端类型或接口不一致。

## 5. 后端服务启动与健康检查

部署者要做什么：

- 启动后端服务。
- 指定前端构建产物目录。
- 检查健康接口。

建议命令：

```bash
uvicorn api.main:app --host 0.0.0.0 --port 8000
```

健康检查：

```bash
curl http://127.0.0.1:8000/health
```

系统内检查：

- 打开 `系统管理` → `系统状态`。
- 打开 `系统管理` → `系统健康`。

失败处理：

- 服务无法启动：检查配置、端口、数据库连接和依赖。
- 健康检查降级：查看影响范围，确认是否可接受。
- 健康检查不可用：停止发布，修复后再开放访问。

## 6. 调度和自动化前置条件

启用调度前必须满足：

- 数据库迁移完成。
- 当前正式策略存在。
- 盘前和盘后数据来源已配置。
- 历史行情数据版本可用。
- 系统时间和交易日配置正确。
- 权限和审计可用。

调度原则：

- 自动化只触发受控维护动作。
- 用户影响动作需要通知或审批。
- 自动化不能静默发布规则、画像或策略。
- 失败必须保留证据并显示修复动作。

## 7. 备份与恢复入口

正式入口：

- `系统管理` → `备份恢复`。

部署者要做什么：

- 配置备份存储位置。
- 在升级前执行备份。
- 定期验证恢复流程。

恢复原则：

- 恢复前确认授权和影响范围。
- 恢复后检查数据库、首页、策略中心、每日盘前和每日盘后。
- 恢复不能丢失正式规则、画像、策略、每日计划和审计证据。

## 8. 日志、观测和错误排查

检查入口：

- `系统管理` → `运行与告警`
- `系统管理` → `系统健康`
- `系统管理` → `权限与审计`

排查顺序：

1. 先确认用户看到的页面状态。
2. 再确认影响范围。
3. 查看运行记录和错误分类。
4. 检查数据版本和配置状态。
5. 执行可恢复动作。

错误展示原则：

- 用户页面说明发生了什么、影响了什么、应该怎么处理。
- 管理员页面可以显示更详细的诊断信息。
- 不把异常堆栈或内部路径暴露为普通用户结论。

## 9. 升级注意事项

升级前：

- 确认工作区无未提交变更。
- 备份数据库和运行配置。
- 记录当前代码版本和数据库迁移版本。
- 运行环境检查。
- 本版本包含规则池批量回测持久化迁移，升级时必须执行数据库迁移并确认迁移位于当前仓库最新版本。

升级中：

- 先更新代码。
- 再安装依赖。
- 再执行数据库迁移。
- 再构建前端。
- 最后启动服务并检查健康。

升级后：

- 检查正式导航。
- 检查首页、研究中心、规则与回测、作者画像、策略中心、每日交易和系统管理。
- 运行必要的路由和构建验证。
- 打开 `规则与回测` → `回测实验`，确认可以看到 `单次正式回测` 和 `规则池批量回测` 两个页签。

## 10. 回滚注意事项

回滚前：

- 判断是代码问题、迁移问题、配置问题还是数据问题。
- 保留失败证据。
- 确认回滚目标版本。

回滚步骤：

- 回滚代码到目标版本。
- 按迁移说明处理数据库状态。
- 必要时从备份恢复。
- 重新启动服务。
- 检查正式路径。

回滚原则：

- 不删除审计历史。
- 不手工覆盖当前正式策略指针。
- 不把不一致状态伪装成成功。

## 11. 常见部署失败

### 环境检查失败

影响：

- 服务可能无法连接数据库或外部服务。

修复：

- 补齐运行时变量。
- 确认部署平台注入方式。
- 重新运行环境检查。

### 数据库连接失败

影响：

- 后端服务不可用。

修复：

- 检查数据库服务、网络、账号权限和连接串。
- 确认数据库已创建。

### 迁移失败

影响：

- 数据结构不符合当前代码要求。

修复：

- 停止发布。
- 保留错误日志。
- 从备份恢复或修复迁移后重试。

### 前端构建失败

影响：

- Web 页面不能发布。

修复：

- 确认 Node.js 18 和 pnpm 可用。
- 重新安装依赖。
- 修复类型或构建错误。

### 浏览器验收失败

影响：

- 正式用户路径未被验证。

修复：

- 查看失败页面。
- 修复路由、数据或接口问题。
- 重新运行浏览器验收。

### 数据状态降级

影响：

- 盘前计划、盘后复盘或回测结论可能不可用或只能观察。

修复：

- 进入 `系统管理` → `数据与调度`。
- 查看缺失范围。
- 执行明确补齐动作。
- 补齐后重新生成相关结果。
