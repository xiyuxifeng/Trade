# WEB-S7-005 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a settings edit service and UI API that can read masked config, expose edit schema, validate drafts, save with backup, list backups, and restore backups with explicit confirmation.

**Architecture:** Keep config-editing behavior in a dedicated `ConfigEditService` so `ConfigService` stays focused on read/mask/template helpers. The API layer should only translate request/response shapes and confirmation flags, while the service owns backup paths, diff generation, validation, and restore semantics. Tests should cover service behavior first, then route behavior, then one API-level smoke path.

**Tech Stack:** Python 3.13, FastAPI, Pydantic, YAML, pytest, existing config loader/mask helpers, existing backup directory conventions under `data/backups`.

def save_config(self, path, draft, *, confirmed=False):
    if not confirmed:
        return ServiceResult(status="error", message="confirmation required")
    backup_path = self._write_backup(path)
    self._write_yaml(path, draft)
    return ServiceResult(status="ok", message="config saved", payload={"backup_path": str(backup_path)})

def restore_backup(self, config_path, backup_path, *, confirmed=False):
    if not confirmed:
        return ServiceResult(status="error", message="confirmation required")
    self._copy_backup_to_config(config_path, backup_path)
    return ServiceResult(status="ok", message="config restored", payload={"backup_path": str(backup_path)})
