## 一、核心目标

建立滚动评估窗口，避免单日噪声触发过拟合调整。

**设计原则：**
- 窗口大小按**交易日**计算（过滤节假日/周末），默认 30 交易日
- 信号在窗口内持续出现（≥50% 交易日）才视为稳定
- 触发调整需同时满足：信号稳定 + 样本量足够（≥10 笔）
- 当前版本为内存存储，进程重启后观察记录清零（不持久化）

---

## 二、配置项（config.py）

```python
@dataclass
class RollingEvaluatorConfig:
    """滚动评估器配置。"""
    window_days: int = 30           # 窗口大小（交易日），默认 30
    min_signal_frequency: float = 0.5  # 信号出现比例阈值（含），默认 50%
    min_sample_trades: int = 10    # 最小有效交易样本量（含），默认 10

    # 交易日历来源（用于过滤节假日/周末）
    # 可注入 trade_dates 函数，若不注入则按自然日近似
    # trade_dates(from_date, to_date) -> list[date]
```

**配置说明：**
- `window_days=30`：30 个有交易的天数，不是自然日
- `min_signal_frequency=0.5`：30 天窗口中，信号至少出现 15 天才算稳定
- `min_sample_trades=10`：窗口内至少 10 笔有效交易才做判断

## 三、核心数据结构

```python
@dataclass
class SignalObservation:
    """窗口内观察到的单条信号。"""
    trader_id: str
    signal_type: str       # 如 "delete_rule" / "upgrade_rule" / "review_stop_loss" / "missed_opportunity"
    rule_id: str
    observation_date: date  # 观察日期（交易日）
    confidence: float       # 建议置信度 0-1


@dataclass
class AdjustmentTrigger:
    """最终触发的调整信号（S7-004 输出）。"""
    trader_id: str
    signal_type: str
    rule_id: str
    trigger_count: int      # 窗口内出现次数
    signal_frequency: float  # 实际出现比例
    observation_count: int  # 窗口内观察总天数
    sample_trades: int      # 窗口内有效交易笔数
    confidence: float       # 平均置信度
```

## 四、接口设计

```python
class RollingEvaluator:
    def __init__(self, config: RollingEvaluatorConfig | None = None):
        self.config = config or RollingEvaluatorConfig()
        self._observations: list[SignalObservation] = []
        self._trade_dates_cache: dict[str, bool] = {}  # 缓存：date -> 是否交易日

    def push_adjustment(self, adjustment: StrategyAdjustment) -> None:
        """将 S7-002 的 RuleAdjustment 加入观察窗口。

        每次调用自动裁剪超窗观察记录（_prune_old_observations）。
        """

    def is_signal_stable(
        self,
        trader_id: str,
        signal_type: str,
        rule_id: str,
    ) -> bool:
        """判断信号是否在窗口内持续出现（≥ min_signal_frequency）。"""

    def has_sufficient_samples(self, trader_id: str) -> bool:
        """判断窗口内样本量是否足够（≥ min_sample_trades）。"""

    def should_trigger_adjustment(
        self,
        trader_id: str,
        signal_type: str,
        rule_id: str,
    ) -> bool:
        """综合判断是否应触发调整（信号稳定 + 样本足够）。"""

    def get_trigger(self, trader_id: str, signal_type: str, rule_id: str) -> AdjustmentTrigger | None:
        """获取触发详情（用于日志/报告）。"""

    def _is_trading_day(self, d: date) -> bool:
        """判断是否为交易日（使用缓存的交易日历）。"""

    def _prune_old_observations(self) -> None:
        """移除超出 window_days 窗口的旧观察记录。"""
```

## 五、窗口裁剪逻辑

```
交易日历（_is_trading_day）：
  输入：date
  输出：True（交易日）/ False（非交易日）

滚动窗口（_prune_old_observations）：
  1. 从 observations 中提取所有 observation_date
  2. 按交易日排序，找到最早的日期
  3. 计算窗口起始日期 = 倒数第 window_days 个交易日
  4. 移除所有早于窗口起始日期的记录
```

**关键：** 用交易日过滤节假日，不是按自然日直接裁剪。

## 六、信号稳定性判断

```python
def is_signal_stable(self, trader_id, signal_type, rule_id) -> bool:
    """窗口内信号出现比例 >= min_signal_frequency"""
    c = self.config
    window_obs = self._get_window_observations(trader_id, signal_type, rule_id)
    if not window_obs:
        return False
    # 窗口内有多少个有交易的日期
    trading_days_in_window = self._count_trading_days_in_window()
    if trading_days_in_window == 0:
        return False
    # 信号出现比例
    frequency = len(window_obs) / trading_days_in_window
    return frequency >= c.min_signal_frequency
```

## 八、测试场景

| 场景 | 输入 | 预期 |
|------|------|------|
| 单日信号不稳定 | 1 条 SignalObservation | `is_signal_stable=False` |
| 15/30 天信号稳定 | 15 天重复信号 | `is_signal_stable=True` |
| 信号出现但样本不足 | 30 天信号，但只有 5 笔交易 | `should_trigger=False` |
| 双重满足触发 | 20/30 天信号 + 15 笔交易 | `should_trigger=True` |
| 进程重启数据清零 | 重启后 | `observations=[]`，从零开始 |
