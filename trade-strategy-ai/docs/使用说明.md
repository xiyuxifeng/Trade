# 使用说明

## 本地安装（无 Docker）

前置：Python 3.11+。

推荐在 workspace 根目录创建统一虚拟环境，然后以 editable 方式安装：

```bash
cd ..
python -m venv .venv
source .venv/bin/activate

cd trade-strategy-ai
pip install -e ".[dev]"
```

## 淘股吧 Cookie 配置

第一版淘股吧抓取需要手工提供登录后的 Cookie。

### 获取方法

1. 在浏览器中登录淘股吧
2. 打开开发者工具
3. 进入 `Network`
4. 刷新一个登录后可访问的淘股吧页面
5. 选择任意请求，找到 `Request Headers`
6. 复制 `Cookie` 整段内容

### 推荐配置方式

推荐通过环境变量注入，再在配置文件中引用：

```bash
export TGB_COOKIE='你的完整 Cookie'
```

然后在 `trade-strategy-ai/config/app.yaml` 中配置：

```yaml
crawl:
  auth:
    tgb.cn:
      mode: cookie
      cookie: "${TGB_COOKIE}"

  # 抓取来源列表（与 auth 分离；支持同站点多作者）
  sources:
    - source: tgb
      site: tgb.cn
      trader_id: trader_a
      author_id: "10461311"
      author_name: "javxsp"
      list_url: "https://www.tgb.cn/user/blog/moreTopic?userID=10461311"
      enabled: true
    - source: tgb
      site: tgb.cn
      trader_id: trader_a
      author_id: "20000000"
      author_name: "another_user"
      list_url: "https://www.tgb.cn/user/blog/moreTopic?userID=20000000"
      enabled: true
```

也可以直接写入配置文件：

```yaml
crawl:
  auth:
    tgb.cn:
      mode: cookie
      cookie: "你的完整 Cookie"

  sources:
    - source: tgb
      site: tgb.cn
      trader_id: trader_a
      author_id: "10461311"
      author_name: "javxsp"
      list_url: "https://www.tgb.cn/user/blog/moreTopic?userID=10461311"
      enabled: true
```

不推荐直接把真实 Cookie 提交到仓库。

### 使用方式

抓取程序会将该 Cookie 作为 HTTP 请求头中的 `Cookie` 使用，用于访问登录后可见的列表页、文章页和评论页。

同一个站点下的多个作者可以共用同一份域名认证配置；未来如果接入其他站点，则在 `crawl.auth` 下增加新的域名项，并在 `crawl.sources` 中增加对应站点来源即可。

程序约束：

- 不在业务 JSONL 产物中保存 Cookie
- 日志中应避免输出完整 Cookie
- 当出现未登录、验证码、`403`、`429` 时应终止或退避

## 3.2 数据监控 Dashboard

### 概述
数据监控 Dashboard 提供数据新鲜度和质量指标的持续监控，支持 CLI 巡检和静态 HTML 输出。

### CLI 命令

```bash
# 终端巡检（输出 Rich 表格）
python -m src.pipeline.dashboard --mode cli

# 生成静态 HTML 报告
python -m src.pipeline.dashboard --mode html

# 同时输出 CLI 和 HTML
python -m src.pipeline.dashboard --mode both
```

### 配置项

`config/app.yaml` 中的 `dashboard` 配置节：

```yaml
dashboard:
  alerts:
    enabled: true
    freshness_threshold_hours: 24   # 数据新鲜度阈值（小时）
    anomaly_rate_threshold: 5.0     # 异常率阈值（%）
  html_output_dir: data/processed/dashboard
  max_anomaly_details: 20
  alert_mode: both
```

### 输出说明

- **CLI 输出**：统计摘要表（记录数/新增数/新鲜度）+ 质量指标表（异常分类统计）+ 告警列表
- **HTML 报告**：包含统计概览、质量详情、异常明细三部分，保存在 `data/processed/dashboard/dashboard.html`
- **告警退出码**：有关键告警时 CLI 返回非零退出码，可用于 cron 告警

## 4. 配置优先级说明

本项目支持多种配置方式，**优先级如下（高→低）**：

1. **命令行参数**（如部分命令的 `--database-url`，极少用）
2. **环境变量**（推荐，`.env` 文件或 shell 里 `export`，如 `DATABASE_URL`、`TGB_COOKIE` 等）
3. **配置文件 `config/app.yaml`**（如 `database.url`、`crawl.auth` 等）
4. **代码默认值**（兜底，不建议依赖）

**实际建议：**
- 数据库连接串（`DATABASE_URL`）：优先写在 `.env` 文件，或直接导出为环境变量。也可在 `config/app.yaml` 的 `database.url` 字段配置。
- Cookie、API Key 等敏感信息：优先用环境变量注入，YAML 里用 `${TGB_COOKIE}` 方式引用。
- 其他业务参数（如抓取作者、调度时间等）：只需在 `config/app.yaml` 里配置。

**举例：**

- `.env` 文件（推荐）：

  ```env
  DATABASE_URL=postgresql+asyncpg://trade:trade@localhost:5432/trade_strategy_ai
  TGB_COOKIE=你的cookie
  ```

- `config/app.yaml` 也可写：

  ```yaml
  database:
    url: "postgresql+asyncpg://trade:trade@localhost:5432/trade_strategy_ai"
  ```

如有多处配置，**优先级高的会覆盖低的**，无需重复设置。

## 7. 交易模式库（Pattern Library）

### 概述

模式库包含三类模式，用于识别和匹配交易机会：

| 类型 | 来源 | 存储位置 |
|------|------|---------|
| `canonical` 教科书经典形态 | 技术分析文献（Edwards & Magee 等） | `data/patterns/canonical/*.yaml` |
| `article` 文章提炼模式 | 从博客文章 LLM 提取 | `data/patterns/article/*.json` |
| `validated` 验证后模式 | 回测验证有效的 article 模式 | `data/patterns/validated/*.json` |

### 已有形态

目前内置 **50 个教科书经典形态**（`data/patterns/canonical/`）：

- **反转类**（35 个）：头肩底/顶、双底/顶、三底/顶、圆弧底、杯柄形、扩散形、岛形顶、RSI/MACD/CCI 背离、成交量高潮/测试、缺口反转、锤子/倒锤子、吞没、早晨/黄昏之星、十字/蜻蜓/墓碑十字、三白兵/三乌鸦、地量见底、均线金叉/死叉
- **延续类**（14 个）：上升/下降/对称三角形、牛市/熊市旗形、尖旗形、矩形、上升/下降楔形、突破缺口、放量突破
- **突破类**（1 个）：布林带收口

### 添加新的教科书形态

在 `data/patterns/canonical/` 下添加 `.yaml` 文件即可：

```bash
# 示例：添加"锤子线"形态
touch data/patterns/canonical/031_hammer.yaml
```

**YAML 格式示例：**

```yaml
schema_version: "v1"
pattern_id: "031_hammer"
name_zh: "锤子线"
name_en: "Hammer"
pattern_type: reversal
timeframe: daily
conditions:
  - field: "body"
    op: "small"
    description_zh: "实体较小（上下影线是实体的2倍以上）"
  - field: "lower_shadow"
    op: "gt_pct"
    value: 60
    description_zh: "下影线长度超过整日的60%"
  - field: "upper_shadow"
    op: "lt_pct"
    value: 10
    description_zh: "上影线很短"
  - field: "volume"
    op: "confirm"
    description_zh: "锤子日放量"
entry_signal: "锤子线次日开盘价高于锤子实体中点时买入"
stop_loss: "锤子低点下方2%"
take_profit: "颈线等幅目标"
source: "canonical"
book_title: "Technical Analysis of Stock Trends"
author: "Edwards & Magee"
page_ref: "Chapter 4"
confidence: 0.70
description_zh: "看涨反转信号：下影线很长，实体在顶部"
```

**关键字段说明：**

| 字段 | 说明 |
|------|------|
| `pattern_id` | 唯一标识，文件名一致 |
| `pattern_type` | `reversal` / `continuation` / `trend_following` / `breakout` 等 |
| `conditions` | 触发条件列表，详见下方操作符 |
| `entry_signal` | 入场信号描述（人可读） |
| `stop_loss` / `take_profit` | 止损/止盈规则 |

**Condition 操作符（op）：**

| op | 说明 | 是否需要 value |
|----|------|--------------|
| `cross_above` | 上穿 | value 为阈值 |
| `cross_below` | 下穿 | value 为阈值 |
| `gt` / `lt` / `eq` | 大于/小于/等于 | value 必填 |
| `higher_high` / `lower_low` | 创新高/新低 | 无 |
| `breakout_up` / `breakout_down` | 向上/向下突破 | 无 |
| `confirm` | 确认信号（量能等） | 无 |
| `decreasing` / `increasing` | 量能萎缩/放大 | 无 |

### 模式库架构说明

```
BlogArticle
  → LLM 提取 strategy_rules
  → ArticlePattern（提炼）
  → 回测验证（历史 K 线）
  → ValidatedPattern（有效）
      ↓
CanonicalPattern（教科书对照）
      ↓
Unified PatternLibrary
```

模式库的设计支持**以文章提炼为主、教科书为辅**的策略发现方式，后续可通过回测验证不断补充有效模式。

### 模式匹配引擎

使用 `PatternMatcher` 在 K 线数据上扫描模式：

```python
from src.persona.pattern_loader import load_pattern_library
from src.persona.pattern_matcher import PatternMatcher, MatcherConfig
from src.persona.mock_data import MockOHLCVSource

# 加载模式库
library = load_pattern_library()

# 创建匹配器（要求所有条件都满足）
matcher = PatternMatcher(library, MatcherConfig(require_all_conditions=True))

# 生成 K 线数据（mock 或真实）
bars = MockOHLCVSource(symbol="000001.SZ", days=60, seed=42).bars()

# 扫描全量 K 线
matches = matcher.scan(bars, symbol="000001.SZ")
print(f"找到 {len(matches)} 个匹配")

# 只扫描最新一根 K 线（实时场景）
latest = matcher.scan_latest(bars, symbol="000001.SZ")
```

**MatcherConfig 参数：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `require_all_conditions` | `True` | `True`=AND（所有条件都满足），`False`=OR（任一条件满足） |
| `min_confidence` | `0.5` | 最低置信度阈值，低于此值的结果被过滤 |

**匹配结果：**

```python
for m in matches:
    print(f"  {m.pattern.name_zh} @ {m.match_date} "
          f"置信度={m.confidence:.0%} "
          f"条件={m.matched_conditions}/{m.total_conditions}")
```
